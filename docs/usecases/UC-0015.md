## Content

### Goal
開発者または CI パイプラインが、ワークスペース設定に定義された複数テストスイートを実行し、TC ID 単位でマージされた形式証跡を生成し、充足度計算とダッシュボード表示の正本とする。

### Trigger
利用者がワークスペースのテスト実行コマンドを実行する、または CI がプルリクエスト検証の一環でテストを実行する。

### Preconditions
ワークスペース設定に suite 定義と証跡出力先が存在し、formal スイートが実行可能であること。

### Main Flow
1. 実行環境がワークスペースルートの設定を解決する。
2. 各 formal スイートが順に実行され、TC タイトル宣言行に基づく ID キーで結果が記録される。
3. supplementary スイートの結果は集約レポートにマージされない。
4. マージ済み集約レポートが生成され、レポート構築とダッシュボードがそれを入力とする。
5. 利用者がダッシュボードで合否・充足度の更新を確認する。

### Alternative Flows
- 子ディレクトリから CLI 実行: 上方向探索で同一ワークスペース設定が解決される。
- スイート失敗: 失敗 TC が証跡に残り、充足度とギャップ一覧に反映される。

### Postconditions
テスト実行結果が単一の集約証跡として品質メトリクスと同期し、未実行・偽装 passed が区別される。
