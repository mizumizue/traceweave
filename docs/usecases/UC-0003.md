## Content

### Goal
開発者および QA/マネージャーが、要件一覧を機能要件と非機能要件に区分して眺め、必要な側だけに絞り込んで品質の抜けや機能偏重を把握する。

### Trigger
利用者が Web ダッシュボード（マトリクスまたは決め事カタログ）または CLI カタログを開く。

### Preconditions
リポジトリ内の要件ドキュメントがパース可能であり、各要件に機能／非機能の区分が付与されていること。

### Main Flow
1. 画面またはカタログに要件件数が表示され、機能要件数と非機能要件数が並んで示される。
2. 要件カード・行・詳細表示において、機能要件と非機能要件が異なるラベルで強調される。
3. 利用者は「機能要件」または「非機能要件」の区分フィルターを選び、該当する要件だけを閲覧する。
4. 決め事カタログでは要件が区分ごとのまとまりとして並び、件数見出しで規模を把握できる。

### Alternative Flows
- 区分未設定の要件が混在する場合: 未分類として扱い、区分フィルターでは除外され、全体表示時に未分類として識別できる。
- CLI から閲覧する場合: カタログ出力に区分ラベルと件数が含まれ、同じ区分で絞り込める。

### Postconditions
利用者は機能要件と非機能要件の規模と内容を混同せず把握し、次に読むべき要件群を選べる。
