## Content

### Goal
プルリクエスト時またはコミット時に、文書のリンク切れ、循環参照、および必須テスト工程の欠落を自動検知して品質劣化を防ぐ。

### Trigger
開発者がプルリクエストを作成または更新し、CIパイプライン（ACT-0003）が起動する。

### Preconditions
リポジトリに `traceweave` が導入され、CI ワークフローで `traceweave check` が設定されていること。

### Main Flow
1. CI ランナーが `traceweave check` コマンドを実行する。
2. コマンドは `docs/` 配下の全文書のスキーマ、依存方向、検証関係（verifies）、および重要要件のテスト充足状態を静的解析する。
3. 不備や必須工程の欠落が検出されなければ、exit code 0 を返し、CI チェックがグリーンとなる。

### Alternative Flows
- 整合性エラーまたは未テスト要件の検出: リンク切れや重要度Highの未テスト要件が存在する場合、詳細なエラーメッセージを出力して exit code 1 で終了し、マージをブロックする。

### Postconditions
品質基準を満たさないコードおよび文書の main ブランチへの混入が自動的に抑止される。
