## Content

### Goal
開発者・QA/マネージャー・プロダクトオーナーが、未テスト要件・結合工程の欠落・ピラミッド不健全性などの検出結果を一覧で把握し、テスト追加やリリース判断の優先順位を決める。

### Trigger
利用者が Web ダッシュボードのギャップとリスクタブを開く、またはマトリクスから要改善要件へ遷移する。

### Preconditions
トレーサビリティレポートが生成され、ギャップ集計が利用可能であること。

### Main Flow
1. 画面に未テスト要件数・結合未実施要件数などのサマリーが表示される。
2. 利用者は未テスト要件一覧を確認し、重要度と業務影響から優先順位を付ける。
3. 利用者は結合テスト未実施一覧を確認し、内結・外結の追加方針を決める。
4. 必要に応じてチェックリスト形式のエクスポートを取得し、バックログやレビュー議事に転記する。
5. 是正後、マトリクスまたは CI 検証で充足度の改善を確認する。

### Alternative Flows
- ギャップゼロ: 一覧が空であることが明示され、リリース準備の材料としてサマリーを共有する。
- プロダクトオーナー参加: 受入・システム工程の不足をリリース判断の議題として扱う。

### Postconditions
検出された品質リスクに対する担当・期限・テスト追加方針がチームで合意される。
