## Content

### Goal
開発者・プロダクトオーナー・アーキテクトが、要求からテストケースまでの V字モデル文書を起票・改定し、プルリクエスト前にスキーマ・依存・充足度の機械検証を通す。

### Trigger
文書の新規作成または改定が完了し、利用者がローカル検証を実行する。

### Preconditions
docs 配下の文書が所定スキーマに従って編集されていること。

### Main Flow
1. 起票者が NEED・REQ・SPEC・DSN・TC などを依存方向と抽象度境界に沿って追加または更新する。
2. 利用者が文書スキーマ検証（lint）を実行し、種別・依存・fence 違反を修正する。
3. 利用者がトレーサビリティ検証コマンドを実行し、循環参照・孤立ノード・重要要件の未充足を確認する。
4. 問題がなければ exit code 0 で終了し、プルリクエストを作成する。
5. CI パイプラインが同一検証を再実行し、main への混入を守る。

### Alternative Flows
- 検証失敗: エラーメッセージに従い依存 ID・verifies・区分メタデータを修正する。
- プロダクトオーナー主導: 要求のみ起票し、要件以降は開発者・アーキテクトが精緻化する。

### Postconditions
リポジトリ内の V字モデル文書が機械的に整合し、下流のレポートとダッシュボードに正しく反映される。
