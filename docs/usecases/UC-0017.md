## Content

### Goal
開発者または QA 担当者がブラウザを開かずにターミナルでトレーサビリティレポートとマトリクスを生成し、ログ・添付ファイル・チャットでレビュー材料を共有する。

### Trigger
利用者がローカルまたは CI ログ取得のために CLI のレポート生成またはマトリクス出力を実行する。

### Preconditions
docs ディレクトリが解析可能であり、出力形式が指定可能であること。

### Main Flow
1. 利用者がレポート生成コマンドを実行し、構造化レポート成果物を得る。
2. 利用者がマトリクス出力コマンドを指定形式で実行し、標準出力またはファイルに集計を得る。
3. 必要に応じて決め事カタログコマンドで種別フィルタ付き一覧を取得する。
4. 出力をプルリクエスト説明・品質レビュー・ステークホルダー向けメールに添付する。
5. 受信者が静的ビルド済みダッシュボードで同一データを視覚的に確認する。

### Alternative Flows
- 検証失敗時: 整合性検証コマンドが先に失敗し、レポート生成前に修正が促される。
- CI 環境: パイプラインが同一コマンドを非対話で実行し、成果物をアーティファクトとして保存する。

### Postconditions
チームが同一のトレーサビリティスナップショットをテキストとビジュアルの両方で参照できる。
