## Content

### Goal
開発者または AI コーディングエージェントが、エディタ内からトレーサビリティ要約・マトリクス・カタログ・品質ギャップ・V字モデル文書を機械可読に取得し、人間のレビューと起票を効率化する。

### Trigger
開発者が MCP サーバーを起動し、エージェントがツール・リソース・プロンプトを呼び出す。

### Preconditions
対象リポジトリに解析可能な docs 文書群が存在し、MCP 連携設定が有効であること。

### Main Flow
1. エージェントがツール一覧を取得し、トレーサビリティ・地層・要件ステータス・ギャップ・マトリクス・カタログ・意思決定の各ツールが利用可能であることを確認する。
2. エージェントが要約またはマトリクスを取得し、未充足要件や工程偏りを把握する。
3. 必要に応じて品質ギャップ確認ツールを strict モードで呼び出し、検証エラーとギャップ一覧を JSON で受け取る。
4. 文書リソースまたは再利用プロンプトを用いて、レビュー・ギャップ分析・V字起票のたたき台を生成する。
5. 開発者が出力を確認し、文書改定やテスト追加を行う。

### Alternative Flows
- MCP 未起動: エージェントは Web ダッシュボードや CLI へのフォールバックを人間に委ねる。
- 要件 ID 未検出: 決定論的な未検出エラーが返り、エージェントは ID の修正を提案する。

### Postconditions
品質情報がチャット文脈に取り込まれ、人間が承認した変更のみがリポジトリに反映される。
