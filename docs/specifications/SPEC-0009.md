## Content

### Contract
Web ダッシュボードのテストケースモーダル内に、対話型テストランナー「Interactive Test Runner」ブロックを組み込む。パラメータファイルが紐づく純粋入出力テストケースの場合、事前定義されたパターン一覧表（Preset Patterns）を表示し、ワンクリックで選択・入力値への反映ができる。さらに、ユーザーがその場で入力値（JSONまたはフィールド）を書き換え、「▶ テストを手動実行 (Run Test)」ボタンを押下すると、即座に `/api/test/run` を呼び出し（またはローカルフォールバック実行し）、実測値と合否結果をアニメーションを伴って更新・観測表示する。一方、単純な入出力のみで完結しないテスト（ファイルI/O、CLI、E2E等）については、無理にUI実行させず「UI実行対象外」として除外表示を行う。

### Inputs
- `node: DocNode`: 選択中のテストケースノード（`inputAnalysis: TestCaseInputAnalysis` を含む）。
- `patterns?: TestCasePattern[]`: ロードされた事前定義パラメータ群。
- `currentInputs: Record<string, any>`: ユーザーが編集した入力パラメータ。

### Outputs
- スクリプト解析結果に基づく状態バッジ（変更可能: `⚡ スクリプト解析: 入力値変更可能` / 除外: `🔒 スクリプト静的解析: UI入力変更不可`）。
- スクリプト解析ルール（`analysisRule`）および客観的分離理由（`reasonDescription`）の表示。
- 入力値変更可能テストにおける変更可能パラメータスキーマ（`fields`）のチップ表示。
- 実行状態表示（実行中スピナー、実行完了バッジ）。
- 期待値（Expected）カードと実測値（Actual）カードのリアルタイム横並び比較。
- 実行ログ・エビデンスのコンソール風表示領域。
- 所要時間（Duration: `X.X ms`）の計測バッジ。
- UI実行対象外テストにおける除外理由、CLI検証コマンド（コピー機能付き）、および自動テストスイート検証方針の表示。

### Errors
- 入力 JSON の構文エラー時は、送信前にインラインで警告を表示し不正実行を抑止する。
- API 接続エラー時はローカルの純粋関数実行エンジンで即座にフォールバック実行する。

### Constraints
- パラメータの切り替えから実行完了・結果描画まで 200ms 以内で完了すること。
- モバイル表示時にも破綻せず、縦スクロールで期待値・実測値の比較が可能なこと。
- 入力変更可否の判定は AI の力業ではなく、決定論的な静的解析ルールの結果に基づき、客観的に分類・表示されること。
- 単純な入出力のみで実行できないテストを無理にモック化してUI実行させず、UI実行対象外として除外すること。
