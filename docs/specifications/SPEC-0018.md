## Content

### Contract
`TraceabilityGraphBuilder` は、パース済みの `DocNode[]` および `TraceGraph` から、描画用ノード（`TraceGraphVisualNode`）と有向エッジ（`TraceGraphVisualEdge`）のコレクションを構築する。各ノードに対して種別に基づく階層レイアウト（層別ランク: need -> actor/usecase -> requirement -> specification/design/decision -> quality/test_case）および衝突回避X/Y座標を決定論的に算出し、選択ノードに対する上流（祖先）・下流（子孫）の探索結果およびパスハイライト情報を計算して提供する。種別フィルタリングでは、原則として全種別（All）を表示し、特定種別群の除外指定（`excludedKinds`）または対象種別指定（`kindFilter`）に基づき表示ノード・エッジを動的に選別する。Web UI 層（`TraceabilityGraphView`）は、算出されたバウンディングボックスに基づき、ワイドコンテナ展開、ネイティブスクロールによる下スクロール許容、Sticky 列ヘッダー、全幅収容（Fit Width）、全画面（フルウィンドウ）表示、および種別トグル除外・全表示リセット操作を調停・提供する。

### Inputs
1. `nodes: DocNode[]`: リポジトリ内の全パース済みドキュメントノード群。
2. `options?: TraceGraphBuildOptions`:
   - `kindFilter?: Set<DocKind> | DocKind[]`: 表示対象とするドキュメント種別セット（未指定時は全種別表示）。
   - `excludedKinds?: Set<DocKind> | DocKind[]`: 除外対象とするドキュメント種別セット（指定された種別のノードおよび接続エッジを描画から除外）。
   - `searchQuery?: string`: ノードIDまたはタイトルに部分一致する絞り込みクエリ文字列。
   - `selectedNodeId?: string | null`: ユーザーが選択中のノードID。
   - `highlightMode?: 'all' | 'upstream' | 'downstream'`: ハイライト方向（上流のみ、下流のみ、または双方向）。

### Outputs
1. `nodes: TraceGraphVisualNode[]`: 描画用ノードリスト。
   - `id`: ノードID。
   - `kind`: 文書種別（need, requirement, specification, design, 等）。
   - `title`: 文書タイトル。
   - `status`: 文書ステータス。
   - `criticality?`: 重要度（high, medium, low）。
   - `test_level?`: テスト工程区分。
   - `x`: 水平描画座標（px）。
   - `y`: 垂直描画座標（px）。
   - `width`: ノード矩形幅（px）。
   - `height`: ノード矩形高さ（px）。
   - `rank`: 階層レイアウトランク（0: Need, 1: Actor/UseCase, 2: Req, 3: Spec/Design/ADR, 4: QA/TC）。
   - `isHighlighted`: 選択ノードまたはその影響パスに含まれるかどうかの真偽値。
   - `isDimmed`: フォーカス外で半透明化すべきかどうかの真偽値。
   - `upstreamCount`: 上流依存ノード数。
   - `downstreamCount`: 下流依存ノード数。
2. `edges: TraceGraphVisualEdge[]`: 描画用エッジリスト。
   - `id`: エッジ一意識別子（`source->target:type`）。
   - `source`: 始点ノードID。
   - `target`: 終点ノードID。
   - `type`: エッジ種別（`depends_on`, `verifies`, `actor_ref`, `requirement_ref`, `link`）。
   - `isHighlighted`: ハイライトされた影響パスに含まれるかどうかの真偽値。
3. `bounds: { minX: number; minY: number; maxX: number; maxY: number; width: number; height: number }`: グラフ全体の描画バウンディングボックス。
4. `stats: { totalNodes: number; visibleNodes: number; totalEdges: number; visibleEdges: number }`: 表示ノード・エッジの統計値。

### Errors
1. 循環参照や自己参照が存在する場合でも、レイアウト計算の無限ループを起こさず、トポロジカル探索において訪問済みセット（`visited: Set<string>`）を用いて安全に停止しなければならない。
2. 参照先IDが存在しない孤立エッジ（dangling reference）が含まれる場合、描画エッジから安全に除外してログまたはスキップとし、グラフ描画全体をクラッシュさせてはならない。

### Constraints
1. **Pure TypeScript Core 原則**: グラフ構造の構築、上流・下流深さ優先探索（DFS/BFS）、および階層レイアウト座標計算は外部ライブラリ（D3, Vis.js 等）に依存せず、純粋な TypeScript ロジック（`src/core/graph/`）で完結し、ミリ秒単位で決定論的（Deterministic）に実行できなければならない。
2. **高速・軽量な SVG 描画**: Web UI でのレンダリングは純粋な React 19 + SVG 要素を採用し、数千個の DOM ノードを消費する重厚な Canvas ライブラリを追加することなく、軽量かつレスポンシブに動作しなければならない。
