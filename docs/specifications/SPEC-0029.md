## Content

### Contract
`docs/test-cases/TC-<STRATUM>-<NNNN>.md` は静的検証仕様である。実行結果は `TestResultsReport`（SPEC-0028）のみが正本。本文は **観測可能な振る舞い** を記述し、自動化の実装手順（モック構成、内部 API 直呼び、テストランナー操作）を Preconditions / Steps / Expected Results に書かない。

#### 原子性
- 1 文書 = 1 オラクル。Steps が複数番号を持つ場合でも、Expected Results は **単一の判定結論** に収束する（同一シナリオの連続操作）。独立シナリオごとに合格・不合格が分かれる場合は文書を分割する（ADR-0010）。

#### 系譜メタデータ（任意）
| フィールド | 型 | 意味 |
|---|---|---|
| `derived_from` | `string` または `string[]` | 分割元 TC ID |
| `supersedes` | `string[]` | 本書が置換する後継 TC ID（退役親に必須） |

`depends_on` は空配列のまま。系譜は上記または `links` への TC 参照で表す。

#### 工程別の記述面（interface fence）
| `test_level` | Preconditions / Steps / Expected に書いてよいこと | 書いてはいけないこと（機械検査対象） |
|---|---|---|
| `unit` | 公開 API・CLI サブコマンドへの入出力 | （UT は実装名を Objective に限り許容。Steps は公開面） |
| `integration_internal` | コンポーネント境界・設定・内部契約 API | `tests/` パス、ランナー操作 |
| `integration_external`, `system`, `acceptance` | 外部 IF（コマンド、HTTP、UI、成果物ファイル） | 実装クラス名（PascalCase 識別子）、`src/` / `tests/` パス、`mock` / `jest` / `vitest`、テストデータファイルパスを Steps の操作として記述 |

`parameter_file` フロントマターは許可する。Steps 内で当該パスを「読み込む」操作として書くのは **外結以上では禁止**（観測はシステムへの入力操作で述べる）。

### Inputs
- フロントマター: ADR-0009 の ID / `test_level` / `test_method` / `verifies`
- 本文セクション: `### Objective`, `### Preconditions`, `### Steps`, `### Expected Results`（順序固定）

### Outputs
- レビュー可能な手順と期待結果のテキスト
- `validateDocs` による fence-lite / 系譜整合（DSN-0024）

### Errors
- `[fence-lite]` 外結以上で実装・自動化語彙が Steps / Preconditions / Expected に含まれる
- 退役 `status` で `supersedes` が空、または参照先 TC が存在しない
- `derived_from` / `supersedes` が TC ID 形式に合致しない

### Constraints
- ID 形式は `TC-(UT|ITa|ITb|ST|UAT)-\\d{4}` または分割 `...-\\d{4}-(0[1-9]|[1-9]\\d)`（ADR-0010）。分割は同一 `<NNNN>` 内の枝番のみ。新規単独 TC は枝番なし。
- 既存文書の違反は警告として報告し、修正は別作業単位で行う（硬化は ADR 改訂で切り替え可能）。
