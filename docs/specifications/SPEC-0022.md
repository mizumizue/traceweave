## Content

### Contract
Web ダッシュボードは、要件の `requirement_class` を画面上の第一級の識別子として提示する。機能要件と非機能要件は短ラベル（`FR` / `NFR`）と見出し語（`機能要件` / `非機能要件`）で区別し、重要度バッジより左側または上側に置く。決め事カタログは要件を区分ごとのまとまりとして並べ、各まとまりの件数を見出しに示す。マトリクスは専用列とクイック条件で区分絞り込みを提供する。詳細インスペクションのヘッダーは文書種別バッジの直後に区分ラベルを置く。クエリパラメータ `reqclass` により区分フィルターを URL と双方向同期する。

### Inputs
1. レポートに含まれる要件区分付きノード・マトリクス行・カタログ項目。
2. 区分フィルター状態 `requirementClassFilter: 'all' | 'functional' | 'non_functional'`（省略時 `all`）。
3. URL クエリパラメータ `reqclass`（許容値はフィルター状態と同一。不正値は `all` へフォールバック）。

### Outputs
1. マトリクス: 要件行に区分列を表示し、`FR` / `NFR` ラベルで識別する。フィルターが `functional` または `non_functional` のとき、一致する区分の要件行のみを残す。区分未設定行は `all` のときのみ残す。
2. 決め事カタログ: 要件項目を「機能要件」群と「非機能要件」群に分け、各群見出しに件数を表示する。要件以外は区分群の後に並べる。
3. 詳細ヘッダー: 文書種別バッジの直後に区分ラベルを表示する（要件以外では省略）。
4. トレーサビリティグラフの要件ノード: 短ラベル `FR` または `NFR` をノード上に表示する。
5. 品質サマリー: 機能要件件数と非機能要件件数を並記する。
6. URL: `reqclass` が `all` のときは省略し、それ以外はクエリに含める。ホーム状態では `requirementClassFilter: 'all'`。

### Errors
1. `reqclass` に許容値以外が指定された場合、例外を出さず `all` にフォールバックする。
2. 区分未設定の要件が混在しても画面全体は描画を継続し、当該項目は未分類として扱う。

### Constraints
1. 区分ラベルの文言は `FR` / `NFR` および `機能要件` / `非機能要件` に固定し、重要度（high/medium/low）と表記を混同しないこと。
2. フィルター再評価はクライアント側で完結し、外部サーバー通信を要しないこと。
3. `reqclass` の履歴追加方針は他の主要フィルターと同様に `pushState` とする。
