## Content

### Contract
テストパラメータファイルは JSON 形式で保存され、複数のテスト入力パターンと期待値を保持する。また、テスト実行 API `POST /api/test/run` は、クライアントから渡された `testCaseId` と任意の入力値 `inputs` を受け取り、登録されたテストロジック（またはターゲット関数）を安全に実行して実測結果オブジェクトを返却する。

### Inputs
1. パラメータファイル（`fixtures/test-cases/*.json`）:
   - `testCaseId: string`: 紐づくテストケースID。
   - `description: string`: パラメータセット全体の説明。
   - `patterns: Array<{ id: string; name: string; inputs: Record<string, any>; expected: any }>`
2. API リクエスト (`POST /api/test/run`):
   - `testCaseId: string`: 実行対象テストケースID。
   - `inputs: Record<string, any>`: 実行に使用するパラメータ入力値。
   - `expected?: any`: オプションの期待値（指定時は一致判定を実施）。

### Outputs
- API レスポンス (`POST /api/test/run`):
  - `testCaseId: string`
  - `status: 'passed' | 'failed' | 'error'`
  - `actual: any`: 実行による実測出力オブジェクトまたはプリミティブ値。
  - `expected: any`: 指定された期待値。
  - `isMatch: boolean`: 実測値と期待値の一致成否。
  - `durationMs: number`: 実行所要時間（ミリ秒、精度小数点1桁）。
  - `logs: string[]`: 実行過程で出力されたデバッグ・検証ログ。
  - `executedAt: string`: ISO 8601 タイムスタンプ。

### Errors
- `ERR_UNKNOWN_TEST_CASE`: 登録されていない `testCaseId` が指定された場合は 404 エラーを返却。
- `ERR_NOT_UI_EXECUTABLE`: 静的解析ルール（副作用有無・外部依存有無・パラメータファイル有無）に基づき UI 実行対象外と判定されたテストケースに対しては 400 エラー（`status: 'error'`）および除外理由を返却。
- `ERR_EXECUTION_FAILED`: テスト対象ロジックの例外発生時は `status: 'error'` およびエラーメッセージを返却。

### Constraints
- テスト実行処理はタイムアウト 3000ms を上限とし、無限ループを抑止すること。
- 改行コードや順序に影響されない決定論的なディープイコール（Deep Equality）比較を行うこと。
- 単純な入出力のみで完結する決定論的純粋ロジック（充足度計算、ピラミッド診断等）のみをホワイトリスト登録し、外部環境（ファイルI/O、DB、CLI、ブラウザ等）に依存するテストは無理に実行せず除外すること。
- UI実行可否は AI のプロンプトや推論ではなく、決定論的な静的解析ルールに基づき客観的に判定すること。
