## Content

### Contract
文書パース処理は、Markdown 文書からフロントマターに加えて `## Content` 以下の各 `### ` 見出しを構造パースし、見出し名をキーとする `sections` オブジェクトを抽出・構築する。また、テストケース（`kind === 'test_case'`）について、ドキュメント単体の静的パース時は `execution_status` を既定で `pending` とし、外部テスト実行結果レポートが与えられた場合に各テストケース ID を照合して最新の実行ステータス（`passed`, `failed`, `pending`, `skipped`）、実測値、および実行ログ・エビデンスを動的に結合する。

### Inputs
- `markdownContent: string`: YAML フロントマター付きの Markdown ドキュメント文字列。
- `kind: DocKind`: 文書の種別。
- `testResultsReport?: TestResultsReport`: オプションのテスト実行結果レポートデータ。

### Outputs
- `sections: Record<string, string>`: 見出し名をキーとし、その本文（トリム済み文字列）を値とする辞書。
- `execution_status: 'passed' | 'failed' | 'pending' | 'skipped'`: テスト実行ステータス（レポート結合値、または既定の `pending`）。
- `actual_result: string | null`: 実行結果レポートの実測値サマリーまたは出力。
- `expected_result: string | null`: 期待値セクションの本文。
- `objective: string | null`: テスト目的・対象セクションの本文。
- `steps: string | null`: テスト手順セクションの本文。
- `evidence_log: string | null`: 実行ログまたはエビデンス文字列。

### Errors
- `ERR_INVALID_STATUS`: `execution_status` に `passed`, `failed`, `pending`, `skipped` 以外の値が指定された場合はバリデーションエラーとする。

### Constraints
- パースおよび結合処理は同期的に実行され、1ファイルあたり 5ms 未満で完了すること。
- 改行コード（CRLF / LF）に依存せず、見出し文字列を正確にキー分割すること。
