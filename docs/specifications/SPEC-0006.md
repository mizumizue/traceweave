## Content

### Contract
文書パース処理は、Markdown 文書からフロントマターに加えて `## Content` 以下の各 `### ` 見出しを構造パースし、見出し名をキーとする `sections` オブジェクトを抽出・構築する。また、`kind === 'test_case'` の場合、フロントマターの `execution_status`（デフォルト: `pending`）および `### Actual Results` の本文を専用プロパティとして抽出・保持する。

### Inputs
- `markdownContent: string`: YAML フロントマター付きの Markdown ドキュメント文字列。
- `kind: DocKind`: 文書の種別。

### Outputs
- `sections: Record<string, string>`: 見出し名をキーとし、その本文（トリム済み文字列）を値とする辞書。
- `execution_status: 'passed' | 'failed' | 'pending' | 'skipped'`: テスト実行ステータス。
- `actual_result: string | null`: 実測値セクションの本文。
- `expected_result: string | null`: 期待値セクションの本文。
- `objective: string | null`: テスト目的・対象セクションの本文。
- `steps: string | null`: テスト手順セクションの本文。

### Errors
- `ERR_INVALID_STATUS`: `execution_status` に `passed`, `failed`, `pending`, `skipped` 以外の値が指定された場合はバリデーションエラーとする。

### Constraints
- パース処理は同期的に実行され、1ファイルあたり 5ms 未満で完了すること。
- 改行コード（CRLF / LF）に依存せず、見出し文字列を正確にキー分割すること。
