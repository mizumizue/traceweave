## Content

### Contract
TraceWeave レポート JSON に `unitCoverage` オブジェクトを含め、単体テスト品質を REQ/SPEC トレーサビリティとは独立した実装カバレッジ軸として提供する。Web ダッシュボードは `tab=unit` で専用ビューを表示する。カバレッジ計測は言語ごとの標準ツールに委譲し、TraceWeave は LCOV 等の標準アーティファクトを消費する。

### Inputs
- `reports/lcov.info`（言語ツールが出力する LCOV。本リポジトリでは `c8` + Node test runner）
- `reports/coverage-summary.json`（`build-coverage-artifacts` が LCOV から正規化生成）
- `reports/coverage-files/`（ファイル単位の行・分岐詳細 JSON）

### Outputs
- `summary.qualityAxes.traceability`: 契約充足度（overallScore, highCriticalityCoverage）
- `summary.qualityAxes.implementation`: 実装網羅率（status, functionCoveragePercent, branchCoveragePercent）
- `unitCoverage.status`: `available` | `pending`
- `unitCoverage.functionCoverage`, `branchCoverage`, `lineCoverage`: 0.0〜1.0
- `unitCoverage.modules[]`: ファイル単位の関数数・カバレッジ
- `strata[level=unit]`: `metricSource: code_coverage`, `branchCoverage` を含む

### Errors
- カバレッジファイル欠落時は `status: pending` とし、レポート構築全体を失敗させない。

### Constraints
- 単体カバレッジは V字トレーサビリティグラフの `verifies` エッジを生成しない（unit TC の verifies は空または DSN のみ）。
- 充足度スコア（REQ-0002）は内結・外結・ST・UAT の実行合格 TC のみを入力とする。
- `npm test` はテスト結果のみ生成する。カバレッジは `npm run test:coverage` で明示的に生成する。
