## Content

### Contract
ワークスペースルートに `.traceweave/config.json` を配置し、文書パス・証跡パス・テスト suite 一覧を宣言する。CLI は `process.cwd()` から親へ設定ファイルを探索する。`traceweave test` は各 suite を順次実行し、suite 出力（fragment または aggregate 直書き）を `traceweave-v1` 形式（`TestResultsReport`）として読み取り、マージ戦略（既定 `fail-wins`）で単一の集約ファイルへ書き込む。ダッシュボードおよび充足度は集約ファイルのみを結合する。

#### suite.capture
| 値 | 意味 |
|---|---|
| `node-test-tap` | Node.js 組み込み test runner + TAP から TC ID を抽出し fragment に書き込む |
| `fragment` | `run` コマンド実行後、宣言された fragment パスの JSON を読み込む |
| `aggregate` | `run` コマンドが集約パスへ直接書き込む前提で実行する |

### Inputs
- `.traceweave/config.json`（UTF-8 JSON）
- 任意: `--workspace <dir>`、環境変数 `TRACEWEAVE_WORKSPACE`

### Outputs
- 集約 `TestResultsReport`（パスは `testResults.aggregate`、既定 `reports/test-results.json`）
- suite ごとの fragment（任意、既定 `reports/suites/<id>.json`）

### Errors
- ワークスペースを解決できない場合: エラーメッセージを返し終了コード非 0
- suite 実行が非 0 終了の場合: 集約マージ後も CLI 終了コード非 0

### Constraints
- 集約マージは決定論的であること。
- 同一 TC ID の競合は `merge.onConflict`（`fail-wins` | `last-wins`）に従うこと。
- モノレポ内の複数 subject（表示名）の同時解決は SPEC-0025 の範囲外とする。
