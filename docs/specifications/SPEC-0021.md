## Content

### Contract
要件文書のフロントマターは、重要度とは独立した必須属性 `requirement_class` を持つ。許容値は `functional`（機能要件）および `non_functional`（非機能要件）のみとする。解析器はこの値を文書ノードへ写し、決め事カタログ項目、マトリクス行、トレーサビリティグラフ描画ノード、およびレポート集計へ同一の値で伝播する。文書検証は欠落および許容値外をエラーとし、黙って別値へ置換してはならない。解析器自体は欠落値でクラッシュせず、未設定として後段へ渡す。

### Inputs
1. 要件文書フロントマターの `requirement_class` フィールド（文字列）。
2. パース済み文書ノード配列（カタログ構築・マトリクス構築・グラフ構築・レポート集計の入力）。
3. カタログ絞り込みオプション `requirementClass?: 'all' | 'functional' | 'non_functional'`（省略時 `all`）。
4. CLI カタログの区分指定（`requirementClass` と同一の許容値。省略時 `all`）。

### Outputs
1. 文書ノード `requirement_class?: 'functional' | 'non_functional'`（要件以外の種別では未設定）。
2. 決め事カタログ項目の同名フィールド、および集計 `requirementClassCounts: { functional: number; non_functional: number; unclassified: number }`。
3. マトリクス行の `requirementClass?: 'functional' | 'non_functional'`（要件行は文書値を写す。要件でない行は未設定）。
4. グラフ描画ノードの `requirement_class?: 'functional' | 'non_functional'`。
5. レポート要約の `functionalRequirementCount` および `nonFunctionalRequirementCount`（要件ノードのうち各区分の件数。未分類はどちらにも含めない）。
6. カタログフィルター結果: `requirementClass` が `all` 以外のとき、要件ノードはその区分と一致するものだけ残す。要件以外の種別はフィルター対象外として残す。
7. 表示ラベル契約:
   - `functional` → 短ラベル `FR`、見出し `機能要件`
   - `non_functional` → 短ラベル `NFR`、見出し `非機能要件`

### Errors
1. 要件文書で `requirement_class` が欠落している場合、文書検証はエラーを返す（黙って `functional` へフォールバックしない）。
2. 値が `functional` / `non_functional` 以外の場合、文書検証はエラーを返す。
3. 解析対象の個別文書が区分未設定でも、解析処理全体は停止せず当該ノードを未分類として継続する。

### Constraints
1. 区分の解釈は決定論的であり、同一入力に対して常に同一の値・件数が得られること。
2. 重要度（`criticality`）と区分は独立であり、一方の値から他方を推論してはならない。
3. 外部ネットワークや非同期処理に依存せず、メモリ内の純粋変換として完了すること。
