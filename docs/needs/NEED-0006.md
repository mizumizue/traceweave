## Content

### Background
TraceWeave は、要求からテストケースに至る V字モデルのトレーサビリティや、工程・手法別のテスト地層密度の可視化を実現してきた。しかし、堅牢なソフトウェア開発においては、テスト充足度という検証軸のみならず、システムが誰のためのものであり（アクター: ACT）、どのような振る舞いを行い（ユースケース: UC）、どのような仕様契約や制約を満たし（仕様: SPEC、要件: REQ）、どのようなアーキテクチャ・モジュール構造で設計され（設計: DSN）、どのようなトレードオフの下で意思決定されたか（ADR）という「アプリケーションの決め事（決定事項・設計規約・システム契約）」そのものを体系的かつ横断的に理解・閲覧できることが不可欠である。

### Problem
1. 現在のダッシュボードや CLI は、要件（REQ）を起点とするテストマトリクスおよびピラミッド診断に特化しており、リポジトリ内に定義されているアクター（ACT）、ユースケース（UC）、設計事項（DSN）、アーキテクチャ意思決定（ADR）、品質方針（QA）などの重要な決め事ドキュメントが画面上に集約・俯瞰できる場所がない。
2. 開発者やアーキテクト、新規参画メンバーが「システムにどのようなアクターが存在し、各アクターがどのユースケースに関与しているか」「特定の設計（DSN）がどの仕様（SPEC）や意思決定（ADR）に支えられているか」を横断的に追跡しようとする際、個別の Markdown ファイルを手動で探索しなければならず認知負荷が高い。
3. 決め事の種類（kind）別の分類フィルタリング、タグやキーワードによる全文横断検索、およびアクター参照（actor_refs）や要件参照（requirement_refs）、設計リンク（links）を辿る相互ナビゲーション機能がダッシュボードに存在しない。

### Desired Outcome
Web ダッシュボードおよび CLI において、トレーサビリティマトリクスと並ぶ主要機能として「アプリケーションの決め事カタログ（Decisions & Specifications Browser）」を提供する。アクター、ユースケース、要件、仕様、設計、意思決定（ADR）、品質保証、要求など全種類の文書を網羅した横断カタログビュー、種別・タグ別フィルター、全文検索、ドキュメント相互の双方向参照リンク、および決め事の網羅率や統計サマリーを提示し、システムの設計・決定事項を一目で深く探索・把握できる環境を実現する。
