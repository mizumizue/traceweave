## Content

### Background
TraceWeave は、要求（NEED）から要件（REQ）、仕様（SPEC）、設計（DSN）、品質方針（QA）、テストケース（TC）に至る V字モデルのトレーサビリティをマトリクス（表形式）や決め事カタログとして管理・提供してきた。表形式は要件ごとの仕様やテスト網羅率を一覧・確認する上で極めて有効であるが、プロジェクトが拡大するにつれて、成果物間の多対多の参照関係、上流要求から下流テストに至る依存の連鎖、および共通設計や外部アクターとの接続関係が網目（Weave）状に複雑化している。

### Problem
1. マトリクス表の行列表現だけでは、ドキュメント全体のトポロジー（階層・ネットワーク構造）や、どのノードが多数の依存を集約しているハブとなっているかを直感的に俯瞰できない。
2. 特定の要件や仕様に変更が生じた際、そのノードから上流へ遡るルート（どの要求を満たすためのものか）や、下流へ波及するルート（どの設計やテストケースが影響を受けるか）という「影響波及パス（Impact Path）」を視覚的に一目で確認することが難しい。
3. 文書種別の層別（Need -> Actor/UseCase -> Requirement -> Specification/Design -> QA/TestCase）の依存方向や、孤立ノード・循環リンクの存在をグラフィカルに探査する手段が提供されていない。

### Desired Outcome
Web ダッシュボード上に「トレーサビリティグラフ（Graph View）」を新設し、全ドキュメントをノード、依存・検証関係を有向エッジとするインタラクティブなネットワークグラフとして視覚化する。ズーム・パン、自動階層レイアウト、種別フィルタリング、選択ノードを起点とした上流・下流トレースパスの強調表示、およびノードクリックによる詳細インスペクションとの完全連動を実現し、直感的で迅速な影響分析と構造把握を可能にする。
