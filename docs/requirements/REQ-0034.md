## Content

### Statement
システムは、工程別テストケース文書（`test_case`）を QA および監査者が自動化実装を読まずに追試できる **契約観点の手順と期待結果** として保持し、実行自動化の詳細は別レイヤ（テストコード・実行レポート）に閉じ込めなければならない。1 文書 1 オラクルの粒度を維持し、過大なケースは分割してトレーサビリティキーを再採番する（ADR-0010）。

### Acceptance Criteria
- AC-001: Given 外結・システム・受入工程のテストケース文書において When Preconditions / Steps / Expected Results を読んだとき Then 操作者・対象システムの境界（CLI、HTTP、UI、生成ファイル等）で説明され、実装クラス名やテストフレームワーク手順のみで構成されていないこと。
- AC-002: Given 任意のテストケース文書において When 複数の独立した合否判定が同一文書に含まれるとき Then レビューまたはガバナンスにより分割が指示され、子ケースは親と同じ 4 桁番号への枝番 ID（`TC-<STRATUM>-<NNNN>-<SS>`）または非分割時のみ層内新規連番とし、`derived_from` / 親の `supersedes` で系譜が追跡できること。
- AC-003: Given テストを自動実行する場合 When 実行証跡が生成されるとき Then 証跡キーは TC 文書 ID と一致し、TC 本文に実行結果や自動化スクリプトの手順を書き戻さないこと（ADR-0006）。
