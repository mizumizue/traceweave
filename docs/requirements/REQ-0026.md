## Content

### Statement
すべての要件は、機能要件（Functional）または非機能要件（Non-Functional）のいずれかに分類されなければならない。この区分は重要度とは独立した第一級の属性として文書メタデータに保持され、パース結果・トレーサビリティレポート・決め事カタログ・マトリクス行から観測できなければならない。

### Acceptance Criteria
- AC-001: Given 要件文書が機能要件または非機能要件として分類されているとき When 文書群を解析した Then 各要件の区分がパース結果およびレポート上の要件属性として欠落なく観測できること。
- AC-002: Given 要件文書の区分が許容値以外または欠落しているとき When 文書検証を実行した Then 当該要件は検証エラーとして報告され、黙って別の区分に置き換えられないこと。
- AC-003: Given 機能要件と非機能要件が混在する文書群 When 決め事カタログまたはマトリクスを構築した Then 要件ごとの区分と、機能要件件数・非機能要件件数の集計が観測できること。
