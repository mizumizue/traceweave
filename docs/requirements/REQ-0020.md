## Content

### Statement
Web ダッシュボードにおいて、要求（NEED）・アクター（ACT）・ユースケース（UC）・要件（REQ）・仕様（SPEC）・設計（DSN）・意思決定（ADR）・品質保証（QA）・テストケース（TC）の各ドキュメントを頂点（Node）、依存関係（`depends_on`）・検証関係（`verifies`）・参照関係（`actor_refs`, `requirement_refs`, `links`）を有向辺（Edge）とする有向グラフを描画し、表示領域のワイド拡大・自然な下スクロール・全画面表示・直感的なズーム/パンおよび全体表示リセット操作を提供しなければならない。

### Acceptance Criteria
- AC-001: Given Web ダッシュボードのメインナビゲーション When 「トレーサビリティグラフ（Traceability Graph）」タブを選択したとき Then 各ドキュメントが種別に応じたバッジ・タイトル付きノードカードとして表示され、ノード間の依存関係が有向矢印で接続されたグラフが描画され、広い画面幅を活用して全体が閲覧できること。
- AC-002: Given グラフ表示エリア When 通常のマウスホイール回転またはコンテナのスクロールバーを操作したとき Then 縦方向に滑らかに下スクロール（下流・多数のノードへのスクロール移動）が行え、Ctrl/Cmd+ホイールまたはズームボタンにより拡大・縮小、ドラッグ操作によりパン（平行移動）が行えること。
- AC-003: Given グラフレイアウト計算 When グラフが構築されるとき Then V字工程の流れ（Need -> Actor/UseCase -> Requirement -> Specification/Design -> QA/TestCase）に沿った階層的（階層ランク別）配置が自動適用され、ノード同士の重なりが最小化されること。
- AC-004: Given 縦方向に多数のノードが並ぶグラフ When ユーザーが下スクロールを行ったとき Then 各列のカテゴリ名（要求、要件、仕様・設計、テスト等）と件数バッジを含む列ヘッダーがスクロール中も視野内に残り、現在のカテゴリ位置が常時視認できること。
- AC-005: Given グラフツールバー When 「全列フィット（Fit Width）」または「全画面表示（Fullscreen / Full Window）」を操作したとき Then 全列が横スクロールなしで収容されるズーム計算が適用され、またはブラウザ全面を活用した最大化グラフ表示とEscキーによる解除が行えること。
