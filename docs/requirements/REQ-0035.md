## Content

### Statement
システムは、自動テスト実行から生成する TC 単位の合否証跡を **形式証跡（formal）** と **補助ハーネス（supplementary）** に分離し、ダッシュボードおよび `execution_status` の正本は formal のみが更新しなければならない。システム・受入工程で実ブラウザ上の振る舞いがオラクルとなる場合、形式証跡は Playwright 等の E2E スイートを主たる自動化手段とし、ソース読取や静的解析のみを formal 証跡の充足とみなしてはならない。

### Acceptance Criteria
- AC-001: Given ワークスペース設定に `evidenceTier: supplementary` のスイートがあるとき When テストスイートを実行して証跡を集約するとき Then 当該スイートの結果は `reports/test-results.json` にマージされないこと。
- AC-002: Given formal スイート内の自動テスト When TAP または Playwright JSON から証跡を生成するとき Then `TC-<STRATUM>-<NNNN>[-SS]:` で始まるテストタイトルのみが TC ID キーとして記録され、タイトル本文中の `TC-` 参照はキーにならないこと。
- AC-003: Given `test_level` が system または acceptance で Steps がブラウザ UI を観測点とする TC When 自動実行証跡を求めるとき Then `tests/e2e/` の formal E2E が存在するか、TC 文書が手動・探索的であることを明示し、補助ハーネスのみで passed と表示されないこと。
