## Content

### Decision
`validateDocs.ts` に TC 専用検査を追加する。セクション抽出は既存の `extractContentBody` と見出し境界を用い、**Preconditions / Steps / Expected Results** のみを interface fence の対象とする。Objective は検証対象の要約として実装名を含み得る。実装ロジックは `tcInterfaceFence.ts` に分離する（ADR-0012）。

### Structure
- `extractTestCaseSection(body, heading)` — `### Steps` 等の節テキストを抽出
- `findTestCaseInterfaceFenceLeaks(sectionText, testLevel)` — `integration_internal` 以上の禁止パターン（実装型・camelCase/snake_case プロパティ・dotted call・テスト自動化語彙）
- `validateTestCaseLineage(meta, allIds)` — `derived_from`, `supersedes`, 退役親の必須 `supersedes`
- `[tc-interface-fence]` 違反は **errors**（lint 失敗）。外結では MCP `` `get_*` `` / `` `check_*` `` backtick を許可

### Data Flow
1. 全 `test_case` をパース後、系譜フィールドを ID 集合と照合。
2. 非退役ケースで fence 対象セクションを走査。
3. warnings / errors を `validateDocs` 戻り値に集約。`check-docs` は errors のみで exit 1。

### Trade-offs
- 正規表現のみでは「CLI で入力する」と「JSON を読み込む」の区別が不完全。意味監査は `traceweave-test-case-review` に委ねる。
- 警告から error への昇格は ADR-0010 Consequences のフォローで切り替える。
