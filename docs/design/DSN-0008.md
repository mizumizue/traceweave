## Content

### Decision
Web ダッシュボードの最上位タブに「決め事カタログ（Decisions & Architecture / 決め事）」を第1級市民（First-class citizen）として新設し、専用のUIコンポーネント（`DecisionsBrowser`）を配置する。さらに、CLI に `catalog` および `decisions` サブコマンドを追加し、`core` レイヤーに `DecisionsCatalogBuilder` を配置して CLI と Web の両方で同一の相互参照解決ロジックを共有する。

### Structure
```text
src/
├── core/
│   ├── decisions/
│   │   └── DecisionsCatalogBuilder.ts   # 全ドキュメントの相互参照解決・集計・フィルタリング純粋ロジック
│   └── models/
│       └── types.ts                     # DecisionsCatalog, EnhancedDocNode, KindCount 等の型定義
├── web/
│   └── src/
│       ├── App.tsx                      # タブ切り替え（matrix, stratum, decisions, gaps）
│       └── components/
│           └── DecisionsBrowser.tsx     # 決め事横断カタログビュー、種別フィルター、相互リンクナビゲーション
└── cli/
    └── index.ts                         # traceweave catalog, traceweave decisions コマンド
```

### Data Flow
1. **データ構築**: `buildTraceWeaveReport`（または CLI / Web）において、パース済み `nodes` から `DecisionsCatalogBuilder.build(nodes)` を実行。
2. **相互参照解決**:
   - `ACT` ノードに対し、自身を参照している `UC`（`actor_refs` に自身を含むもの）を逆引き紐付け。
   - `UC` ノードに対し、参照先の `ACT`（`actor_refs`）および対象 `REQ`（`requirement_refs`）を紐付け。
   - `DSN` ノードに対し、参照先の `SPEC`（`depends_on`）および関連 `ADR`（`links`）を紐付け。
   - `ADR` ノードに対し、関連 `DSN`（`links`）および波及する仕様を紐付け。
3. **Web ダッシュボード描画**: `App.tsx` から `report.catalog` を `DecisionsBrowser` に渡し、種別バッジチップ、タグピル、全文検索、カード表示、およびクリック時のモーダル詳細表示（履歴スタック連動）を即時実行。
4. **CLI 表示**: `traceweave catalog` は全ノードまたは指定種別（`--kind`）をテーブル表示し、`traceweave decisions` は ADR と DSN に焦点を当てた関係一覧をターミナル出力。

### Trade-offs
- **独立タブの追加 vs マトリクス内統合**: マトリクス表内にアクターやADRを無理に列として埋め込むと、REQ中心のV字モデルの視認性が低下し、アクターやADR自体の広範な目的が埋没する。独立した「決め事カタログ」タブを設けることで、トレーサビリティの明瞭さを保ちながら、システム全体の決め事を多角的に探索できる。
- **Coreロジック共有**: ブラウザ側（React）だけでフィルタリングするのではなく、`core/decisions` にビルダーを設けることで、CLIのJSON/Markdown/Text出力や自動テストとの一貫性を担保する。
