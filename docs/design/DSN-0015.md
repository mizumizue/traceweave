## Content

### Decision
ソフトウェアテストの5大工程（単体・内部結合・外部結合・システム・受入）におけるテストケース件数、全体構成比率、および要件カバー率を直感的に診断するため、立体感を持つ階層型ピラミッドコンポーネント `VisualTestPyramid` を設計する。
各層の視覚的な幅比率計算（`calculatePyramidTierWidths`）を純粋関数として分離し、外部グラフィックライブラリに依存せず、CSS / Tailwind の台形スタック構造と `CircularGauge`（DSN-0013）の合成により軽量かつ高い情報密度で描画する。さらに、各層をクリックすることでトレーサビリティマトリクス表の工程フィルター（`phaseFilter`）と即座に連動するインタラクティブな双方向操作を提供する。

### Structure
1. **純粋幅計算ヘルパー**: `src/web/src/components/VisualTestPyramid.tsx`
   - `calculatePyramidTierWidths(strata)`:
     - 全工程の総テスト件数を算出。
     - 各工程（Unit 〜 Acceptance）の構成比率（$P_i = \text{count}_i / \text{total}$）を算出。
     - 最上層（Acceptance: 最小幅 45%）から最下層（Unit: 最大幅 100%）にかけて、テスト件数の多寡を反映しつつ台形形状を維持する視覚幅（`widthPercentage`）を正規化算出。
2. **コンポーネント構造**:
   - `VisualTestPyramid`:
     - 診断ステータスヘッダー: ピラミッド健全性バッジ（Healthy, InvertedIceCream, HollowHourglass 等）および警告・推奨アクション。
     - ピラミッド階層コンテナ:
       - 上から Acceptance → System → Integration External → Integration Internal → Unit の順に配置。
       - 各階層ブロック: クリック可能なボタンカード、工程名・略称、テスト件数バッジ、構成比率（%）、および要件充足度を示すインライン `CircularGauge`。

### Data Flow
1. 親ビュー（`StratumView` または `App.tsx`）から解析済みの `strata`（工程別充足度レポート）および `pyramid`（健全性診断結果）を受領。
2. `calculatePyramidTierWidths` が実行され、各層のテスト件数、構成比率、描画幅、密度ステータス（Heavy, Adequate, Thin, Missing）を整理。
3. ユーザーが特定の層（例: `Integration Internal`）をクリックすると、`onSelectPhase('integration_internal')` コールバックが発火。
4. 親の `App.tsx` が `phaseFilter` を更新し、タブをマトリクスビューへ遷移させ、対象工程のテストケースのみを即座に絞り込み表示。

### Trade-offs
- **真の三角形ポリゴン SVG 描画 vs 横長台形スタックカード方式**:
  - 純粋な三角形ポリゴンでピラミッドを描画した場合、上部（尖った部分）の描画領域が極端に狭くなり、テキストラベルや円形ゲージ、テスト件数が潰れて視認できなくなる。
  - 最低幅 45% を担保した横長台形スタックカード方式を採用することで、ピラミッドとしての全体的な階層形状を美しく表現しつつ、各層の数値・ゲージ・ラベルの視認性とクリック操作性を両立させた。
