## Content

### Decision
lucid-memories の ADR-0008（「フロントエンドのsrc配下移設と組み込みUIの完全統合」）および ADR-0006（「スクリプト資産の一元管理とルート直下からの撤去」）の指針に厳格に準拠し、リポジトリルート直下に散在していた Web 開発資材一式（`index.html`, `vite.config.ts`, `tailwind.config.js`, `postcss.config.js`）を `src/web/` 配下に完全カプセル化する。また、ビルド生成物の出力先をルート直下の `dist-web/` から TypeScript 出力と同一階層の `dist/web/` に集約・統合する。さらに、ルート直下にはガバナンスと全体構成マップを提示する `DEVELOPER_GUIDE.md` を配置する。

### Structure
リポジトリ全体のディレクトリ構造を以下のように再編する：

```text
traceweave/
├── README.md               # 製品概要、全体構成マップ、クイックスタート
├── ARCHITECTURE.md         # アーキテクチャ設計原則、レイヤー責務、システム構造図
├── DEVELOPER_GUIDE.md      # 開発者ガイド: 文書先行プロセスの流れ・リポジトリ構造規約
├── package.json            # プロジェクト基盤メタデータ・依存関係・スクリプト
├── package-lock.json       # 依存関係ロックファイル
├── tsconfig.json           # TypeScript コンパイラ設定
├── .gitignore              # Git 除外設定（dist/, node_modules/ 等）
│
├── docs/                   # 【製品の決め事】要求・要件・仕様・設計・ADR・品質・テスト
├── fixtures/               # テスト用フィクスチャ
├── scripts/                # 運用・検証スクリプト (validate-docs.ts)
├── tests/                  # 単体・結合・E2Eテストスイート
│
├── src/                    # 【アプリケーションコード集約】
│   ├── core/               # ドメイン中核ロジック（純粋 TypeScript・外部依存ゼロ）
│   ├── application/        # ユースケースオーケストレーション
│   ├── infrastructure/     # ファイル I/O・SQLite キャッシュ・レポーター
│   ├── cli/                # CLI コマンド受付（Commander.js）
│   ├── mcp/                # Cursor / AI エージェント連携用 MCP サーバー
│   └── web/                # 【Web ダッシュボード開発資材・UI コンポーネント完全カプセル化】
│       ├── index.html      # 起点 HTML
│       ├── vite.config.ts  # Vite バンドル設定
│       ├── tailwind.config.js # Tailwind CSS 設定
│       ├── postcss.config.js  # PostCSS 設定
│       └── src/            # React 19 UI ソースコード
│           ├── App.tsx
│           ├── main.tsx
│           ├── index.css
│           └── components/
│
└── dist/                   # 【ビルド成果物集約】（.gitignore 対象）
    ├── cli/                # コンパイル済み CLI
    ├── core/               # コンパイル済み Core
    └── web/                # ビルド済み静的 Web アセット（index.html, JS/CSS, data.json）
```

### Data Flow
1. **ビルド時**: `npm run build:web` 実行時、Vite は `src/web/vite.config.ts` を読み込み、`src/web/index.html` を起点としてバンドルを実行し、`dist/web/` に静的ファイルを生成する。続いて CLI `traceweave build --out ./dist/web` が実行され、トレーサビリティ集計結果 `data.json` が `dist/web/data.json` に出力される。
2. **ローカル配信時**: `traceweave serve` は `./dist/web` を静的アセットディレクトリとして優先的に参照し、ブラウザへ提供する。存在しない場合はフォールバック動的 HTML を配信する。

### Trade-offs
- Vite 実行時に `--config src/web/vite.config.ts` を指定する必要があるが、`package.json` のスクリプトとして抽象化されるため、日常の開発作業におけるオーバーヘッドはない。
- リポジトリルートから個別技術（Vite/Tailwind）のノイズが完全に排除され、製品ガバナンスと全体構成の可視性が飛躍的に向上する。
