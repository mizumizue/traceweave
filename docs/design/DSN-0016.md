## Content

### Decision
トレーサビリティマトリクス表における大量行の探索性を高めるため、重要度（Criticality）、テスト工程（Phase）、品質充足度（Sufficiency Status）、およびフリーワード検索（Keyword）の4軸条件をクライアント側で高速に評価する純粋フィルター関数 `filterMatrixRows` を導入する。
さらに、外部サーバーへの API 通信やバックエンド依存を一切排除し、ブラウザのインメモリデータから CSV、JSON、および Markdown 形式のデータをオンザフライで生成・ダウンロードできる完全クライアントサイドエクスポート機構を設計する。

### Structure
1. **データ処理モジュール**: `src/web/src/utils/matrixData.ts`
   - `filterMatrixRows(rows, filters)`:
     - 各マトリクス行に対し、重要度一致、工程別テスト存在確認、充足度ステータス（100%、1%〜99%、0%）一致、および ID/タイトル/タグに対する部分一致（大文字小文字不問）を $O(N)$ で高速評価。
   - `serializeMatrixCsv(rows)`: RFC 4180 準拠の CSV 文字列シリアライザ（エスケープ処理付き）。
   - `serializeReportJson(report)`: フォーマット済み JSON 文字列シリアライザ。
   - `serializeSummaryMarkdown(report)`: GitHub やチケット起票に即座に貼付可能な Markdown 表形式シリアライザ。
   - `triggerBlobDownload(content, filename, mimeType)`: `Blob` オブジェクトと一時的な `<a download>` による決定論的ダウンロードヘルパー。
2. **UI コンポーネント構造**: `src/web/src/components/MatrixView.tsx`
   - コントロールツールバー: 検索インプット、重要度セレクト、工程セレクト、充足度セレクト、クイックチップ（ワンクリック解除）、エクスポートボタングループ。
   - マトリクスグリッド: フィルタリング結果行のレンダリング。

### Data Flow
1. **リアルタイム絞り込み**:
   - 利用者がフィルター条件を変更すると、React の `useMemo` を介して `filterMatrixRows` が同期実行される。
   - 100件以上の要件・仕様・テストケース行であっても数ミリ秒でフィルタリングが完了し、テーブルが即時再描画される。
2. **エクスポート実行**:
   - 利用者が「CSV エクスポート」をクリックすると、`serializeMatrixCsv(filteredRows)` によりメモリ上で CSV 文字列が生成される。
   - `triggerBlobDownload` が呼ばれ、`URL.createObjectURL(blob)` から一時リンクが生成・自動クリックされ、ブラウザの標準ダウンロードが実行される。
   - 完了後に `toast.success` が発行され、ユーザーにフィードバックを提供。

### Trade-offs
- **サーバーサイドエクスポート vs クライアントサイド完結**:
  - サーバーサイドで CSV や JSON を生成・ダウンロードする場合、ネットワークレイテンシやサーバー負荷が発生し、静的ホスティング（GitHub Pages 等）環境では動作しない。
  - すべてのトレーサビリティデータは初期ロード時にクライアント側に供給されているため、ブラウザ側で純粋関数としてシリアライズを行うことで、オフラインでも 100% 動作し、即座にダウンロードを完了できる。
- **デバウンス検索 vs 即時フィルタリング**:
  - 数千行規模であればデバウンスが必要だが、本システムのドキュメント数（数十〜数百件）では $O(N)$ のインメモリ文字列検索が 5ms 未満で完了するため、デバウンスの遅延感を排除した即時反映方式を採用した。
