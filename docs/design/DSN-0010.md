## Content

### Decision
1. **URLStateController モジュールの導入**:
   React コンポーネントツリーとブラウザ History API の間に、純粋関数および状態シリアライザ/デシリアライザとして機能する `urlState.ts` を新設する。
   これにより、URL クエリ文字列のパース、バリデーション、クリーンな URL 文字列生成、および `pushState` / `replaceState` 判定ロジックを UI レンダリングから分離し、単体テスト可能とする。
2. **popstate ループ防止の同期フラグパターン**:
   ブラウザバック（`popstate`）によって内部 React State を更新する際、それが通常の「ユーザー操作による State 変化」とみなされて二重に `pushState` を発行してしまう循環参照バグを防ぐため、`isNavigatingFromPopstate` フラグによるガード構造を設ける。
3. **履歴スタック（push vs replace）の明示的制御**:
   - `pushState`: ユーザーが明示的に画面を切り替えたとき（タブ変更、ノード選択によるモーダル開閉、ノードリンク遷移、主要フィルターの選択変更）。
   - `replaceState`: 検索文字列（`q`）のキーストローク入力、初期化時の正規化、またはすでに同じ状態の場合。
4. **URL共有（Share Link）アクションの追加**:
   ヘッダーツールバーにリンクアイコン付きの「URL共有」ボタンを追加し、現在のアクティブタブ・開いているモーダル・フィルター条件が反映された完全な URL をワンクリックでクリップボードにコピーできるようにする。

### Data Flow
1. **初期ロード時**:
   - `App.tsx` マウント時に `window.location.search` を読み取り、`parseUrlState()` により初期状態オブジェクトを生成。
   - 各ステート（`activeTab`, `selectedNodeId`, `phaseFilter` 等）の初期値として反映。
   - レポートデータ取得完了後、`node` パラメータで指定されたノードが実在すればモーダルを自動展開。
2. **ユーザー操作時（例: タブ変更・ノードクリック）**:
   - ハンドラー内でステートが更新される。
   - `useEffect` または専用の同期ハンドラーが、最新の状態から `serializeUrlState()` で URL クエリ文字列を生成。
   - `isNavigatingFromPopstate` フラグが false の場合、`window.history.pushState(null, '', newUrl)` を呼び出してブラウザ履歴に追加。
3. **ブラウザバック / 進む操作時（popstate 発火）**:
   - `window.addEventListener('popstate')` が発火。
   - `isNavigatingFromPopstate = true` に設定。
   - 現在の `window.location.search` から `parseUrlState()` で状態を取得し、React ステート群を一括更新。
   - レンダリング完了後に `isNavigatingFromPopstate = false` に復帰。

### Trade-offs
- **パスルーティング（`/graph`, `/decisions`）vs クエリパラメータ（`?tab=graph`）**:
  - 静的ホスティング（GitHub Pages やローカル static server）では、パスルーティングを使用するとリロード時に 404 が発生しやすいため、サーバー設定不要で確実に動くクエリパラメータ方式を採用。
- **全パラメータ即座 pushState vs デバウンス**:
  - 検索ボックスなどのテキスト入力で 1 文字ごとに pushState を呼ぶと履歴スタックが溢れてブラウザバックが壊れるため、検索入力は replaceState、タブやノード選択などの明確な遷移のみ pushState とするハイブリッド方式を採用。
