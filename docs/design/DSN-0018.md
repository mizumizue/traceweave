## Content

### Decision
機能要件と非機能要件の見た目を一箇所に集約するため、共有バッジ `RequirementClassBadge` を導入する。色は機能要件をエメラルド、非機能要件をアンバーとし、重要度（rose/amber/slate）と短ラベルが衝突しないよう区分は `FR` / `NFR` を先行表示する。カタログは core の分割結果をセクション見出し付きで描画し、マトリクスは区分列とクイックチップを重要度フィルターより左（または上）に置く。URL は既存 `urlState.ts` に `requirementClassFilter` とクエリ `reqclass` を追加する。

### Structure
```text
src/web/src/
  components/
    RequirementClassBadge.tsx   # FR/NFR 共通バッジ（短ラベル＋任意で見出し語）
    MatrixView.tsx              # 区分列、セレクト、クイックチップ
    DecisionsBrowser.tsx        # 区分フィルターと FR/NFR セクション
    NodeDetailModal.tsx         # 種別バッジ直後の区分バッジ
    TraceabilityGraphView.tsx   # 要件ノード上の FR/NFR
    QualityMetricsGrid.tsx      # 要件カード内の FR/NFR 件数
    GapsView.tsx                # ギャップ行の区分バッジ
  utils/
    urlState.ts                 # requirementClassFilter / reqclass
    matrixData.ts               # filterMatrixRows の区分条件、CSV 列
```

### Data Flow
1. `App.tsx` が URL 初期値から `requirementClassFilter` を復元し、マトリクス・カタログ・履歴同期へ渡す。
2. マトリクスは `filterMatrixRows(..., { requirementClass })` で絞り、列セルは `RequirementClassBadge` を描画する。
3. カタログはクライアント側でも区分フィルターを適用したうえで、`partitionByRequirementClass` の順（機能要件 → 非機能要件 → その他）でセクション描画する。
4. 詳細モーダルは `node.kind === 'requirement'` のとき種別バッジの直後にバッジを置く。
5. ホーム遷移は `requirementClassFilter: 'all'` を含む `DEFAULT_URL_STATE` へ戻す。

### Trade-offs
- **独立タブ vs 既存ビューへの埋め込み**: 区分専用タブを増やすとマトリクス／カタログとの二重管理になる。既存の要件観測面に列・セクション・バッジを足す方が、区分が「要件の読み方」であることが伝わる。
- **グラフから非該当ノードを除外 vs バッジのみ**: 除外はエッジが切れトポロジーが壊れる。グラフはバッジで強調し、絞り込みはマトリクスとカタログに担わせる。
- **CSS 変数 vs 固定トークン**: ダッシュボードは既存の Tailwind トークン体系で統一されているため、区分色も同系の emerald / amber に固定し、テーマ機構は導入しない。
