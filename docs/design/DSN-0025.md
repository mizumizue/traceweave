## Content

### Decision
形式 TC キーの抽出は `testCaseId.ts` の `formalTestCaseIdFromTitle` に単一化する。TAP 変換（`parseTapTestReport.ts`）と Playwright JSON 変換（`playwrightReportToTraceWeaveV1.ts`）はいずれもこの関数を呼ぶ。

### Structure
- `formalTestCaseIdFromTitle(title)` — 行頭 `TC-...:` のみ。`extractTestCaseIds` はガバナンス・ログ用に残し、証跡マージでは使わない。
- `run-workspace-tests.ts` — スイート実行後、`evidenceTier === 'formal'` の fragment だけを `mergeTestResultsReports` に渡す（`mergeOnly` も同規則）。
- `run-node-test-tap-suite.ts` — `FORMAL_EXCLUDE_DIRS = support, e2e`；`testsDir` 指定時はその配下のみ列挙。
- `scripts/run-e2e-suite.ts` — `build:web` 確保 → Playwright CLI → raw JSON → `playwrightReportToTraceWeaveV1` → `reports/suites/e2e.json`。

### Data Flow
1. Node TAP: サブテスト完全タイトル → `formalTestCaseIdFromTitle` → `TestResultsReport.results`
2. Playwright: spec タイトル（リーフ）→ 同上
3. `runWorkspaceTests` が formal fragments をマージ → `reports/test-results.json`

### Trade-offs
- Playwright 未インストール環境では E2E は失敗または `TW_SKIP_E2E=1` でスキップ。CI は lint 中心のため E2E はローカル／別ジョブ想定。
- `support:` ハーネスは引き続き人間可読性のため本文に旧 TC 番号を含め得るが、証跡には載らない。
