## Content

### Decision
トレーサビリティグラフ構築・充足度スコアリング・工程地層分析およびピラミッド/トロフィー構成診断の中核ロジックを `src/core/` に集約し、Node.js やファイルシステム、特定の UI ライブラリ、CLI ライブラリに一切依存しない「Pure TypeScript」として設計する。

### Structure
- `src/core/models/`: ノード、エッジ、工程、手法、スコア、ピラミッド/トロフィー診断等の純粋型定義
- `src/core/graph/`: 有向グラフ、依存チェーン探索、Tarjan/DFS循環検知
- `src/core/sufficiency/`: 品質充足度スコア計算ロジック。工程加算は実行ステータス `passed` のテストケースのみ。文書件数は別集計として保持する。
- `src/core/analyzer/`: 工程地層密度および多元テスト構成（ピラミッド・トロフィー健全性、不均衡・欠落）診断ロジック。入力の工程件数は充足度計算の実行合格件数と同一とする。
- `src/application/`: 各ユースケース（バリデーション、マトリクス集約、レポート生成）のオーケストレーション
- `src/infrastructure/`: ファイルI/O（gray-matter）、SQLiteキャッシュ、コンソールレポーター
- `src/cli/`, `src/web/`, `src/mcp/`: 外部インターフェース層

### Data Flow
1. Entrypoint（CLI / Web / MCP）が Application サービスを起動。
2. Application は Infrastructure を通じて文書データを読み込み、Core のエンティティおよびグラフへ変換。
3. Core が純粋関数・ドメインモデルとして計算（実行合格ベースのスコア、地層、ピラミッド/トロフィー診断）を実行。未実行ノードはスコアに流入しない。
4. Application は計算結果を受け取り、出力形式（JSON, Markdown, HTML, Console）に合わせて Entrypoint へ返却。

### Trade-offs
- メリット: ドメインロジックの単体テストが爆速（ミリ秒）で実行可能。CLI・Webダッシュボード・MCPサーバー間で同一の型とロジックを100%共有でき、バグや不整合が起きない。
- デメリット: レイヤー分離に伴うインターフェース（ポート）定義の手間が若干増えるが、長期的な保守性・可読性のメリットが遥かに上回る。
