## Content

### Decision
Web ダッシュボードにおける操作フィードバック基盤として、軽量かつスタックアニメーションに優れた公式 `sonner` ライブラリを採用する。
ルートコンポーネント（`App.tsx`）の最上位階層に `<Toaster />` を常駐マウントし、モーダルダイアログやグラフ表示の前面（高い z-index）で動作させる。各子コンポーネント（ヘッダー、モーダル、対話型テストランナー等）からは、ステートを直接受け渡すことなく `toast` インターフェースを通じて非同期ローディングおよび成否通知を発行する。

### Structure
1. **マウント構造**:
   - `src/web/src/App.tsx`:
     - `<Toaster position="bottom-right" theme="dark" richColors closeButton />`
2. **通知発行コンポーネント群**:
   - `Header.tsx`: サマリー Markdown コピー、共有 URL コピー、CSV / JSON エクスポート時の成功/失敗通知。
   - `InteractiveTestRunner.tsx`: テスト実行開始時のローディングトースト、合否結果確定時のサクセス/エラートースト。
   - `NodeDetailModal.tsx`: ノード ID / パス / Markdown 本文コピー完了通知。
   - `urlState.ts` 連携: 存在しないノードへの直接アクセス時の警告通知。

### Data Flow
1. ユーザー操作（例: 「テストを手動実行」ボタン押下、または「URL共有」ボタン押下）。
2. 発行元コンポーネントが `toast.loading('実行中...')` または即時 `toast.success('コピー完了')` を呼び出し。
3. 長時間処理（API テスト実行など）の場合、返却されたトースト ID に対し完了時に `toast.success('成功', { id: toastId })` または `toast.error('失敗', { id: toastId })` で同一通知をインプレース更新。
4. 設定された表示時間（デフォルト 3000ms）経過後、またはユーザーによるクローズ操作により、DOM から自然に退出アニメーションを伴って消去。

### Trade-offs
- **独自コンポーネント自作 vs sonner**:
  - 独自でトーストコンポーネントを実装する場合、スタッキングアニメーション、ジェスチャースワイプ消去、z-index 競合回避、タイマー制御など多大な実装・保守コストが発生する。
  - `sonner` は約 3KB の超軽量フットプリントであり、React 19 に完全対応し、ダークモードや Tailwind CSS との整合性も極めて高いため、外部ライブラリ採用のメリットが開発コストを大幅に上回る。
- **コンテキスト Provider 方式 vs シングルトン API**:
  - `sonner` は React Context を必要とせず、任意の関数やコールバックから直接 `toast(...)` を呼び出せるため、コンポーネントの props リレー（バケツリレー）を完全に排除できる。
