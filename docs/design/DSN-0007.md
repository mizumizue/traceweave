## Content

### Decision
lucid-memories のアーキテクチャ指針（「ルート直下は製品のガバナンス・決め事・全体構成マップを最前面に配置し、実装コード・依存・生成物は src/ 配下に集約する」「bin/ 配下にラッパースクリプトを配置してルートから透過実行する」）に完全準拠し、リポジトリルートに存在していた `package.json`、`package-lock.json`、`tsconfig.json`、`node_modules/`、および `dist/` を `src/` 配下に完全カプセル化する。ルート直下には `bin/traceweave` ラッパーを提供し、`NODE_PATH` を自動注入して実行する。

### Structure
リポジトリ全体の最終配置構造：

```text
traceweave/
├── README.md               # 製品概要、全体構成マップ、クイックスタート
├── ARCHITECTURE.md         # アーキテクチャ設計原則、レイヤー責務、システム構造図
├── DEVELOPER_GUIDE.md      # 開発者ガイド: 文書先行プロセスの流れ・リポジトリ規約
├── .gitignore              # Git 除外設定（src/node_modules/, src/dist/, .cache/ 等）
├── .cursorignore           # Cursor インデックス除外設定
│
├── docs/                   # 【製品の決め事】要求・要件・仕様・設計・ADR・品質・テスト
├── fixtures/               # テスト用フィクスチャ
├── scripts/                # 運用・検証スクリプト (validate-docs.ts, run-tests.sh 等)
├── tests/                  # 単体・結合・E2Eテストスイート
├── bin/                    # 【透過実行ラッパースクリプト】
│   ├── traceweave          # POSIX bash ラッパー
│   ├── traceweave.cmd      # Windows cmd ラッパー
│   └── traceweave.ps1      # Windows PowerShell ラッパー
│
└── src/                    # 【アプリケーション実装・依存・成果物集約】
    ├── package.json        # 依存関係・ビルドスクリプト定義
    ├── package-lock.json   # 依存関係ロックファイル
    ├── tsconfig.json       # TypeScript 設定
    ├── node_modules/       # プロジェクト依存パッケージ（.gitignore 対象）
    ├── dist/               # コンパイル済み成果物（.gitignore 対象）
    ├── core/               # 純粋 TypeScript コア（外部依存ゼロ）
    ├── application/        # ユースケースオーケストレーション
    ├── infrastructure/     # ファイル I/O・SQLite キャッシュ・レポーター
    ├── cli/                # CLI コマンド受付（Commander.js）
    ├── mcp/                # Cursor / AI エージェント連携用 MCP サーバー
    └── web/                # Web ダッシュボード開発資材・UI コンポーネント
        ├── index.html
        ├── vite.config.ts
        ├── tailwind.config.js
        ├── postcss.config.js
        ├── dist/           # Web ビルド成果物（.gitignore 対象）
        └── src/            # React 19 UI ソースコード
```

### Data Flow
1. **CLI 実行フロー**: 利用者が `./bin/traceweave report` を実行すると、ラッパーがリポジトリルートを検出し、`NODE_PATH="$ROOT/src/node_modules"` をエクスポートした上で、コンパイル済みの `src/dist/cli/index.js`（または TypeScript 実行環境）を起動する。
2. **ビルドフロー**: `npm --prefix src run build` または `./bin/traceweave build` により、TypeScript のコンパイル結果は `src/dist/` に、Web 静的バンドルは `src/web/dist/` に出力される。ルート直下にはいかなる生成物も出力されない。
3. **テスト実行フロー**: テストランナー（`scripts/test.sh` または `npm --prefix src test`）が `NODE_PATH` を介して `src/node_modules` を参照し、`tests/` 配下の全テストスイートを実行する。

### Trade-offs
- ルート直下で素の `npm install` や `npm test` を叩く代わりに、`npm --prefix src install` や `./bin/traceweave`、あるいはラッパースクリプトを利用する必要がある。
- その代償として、リポジトリルート直下から `node_modules/` の数千ファイルや `dist/` のバイナリ・生成物が 100% 完全に消滅し、lucid-memories と同等の高い規律と美しさを兼ね備えたリポジトリ構造が得られる。
