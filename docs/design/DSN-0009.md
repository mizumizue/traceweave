## Content

### Decision
外部の重厚なグラフ可視化ライブラリ（Cytoscape.js, D3-force, Vis-network 等）を追加せず、TraceWeave のアーキテクチャ原則「Pure TypeScript Core (Zero External Dependencies)」および「軽量かつ超高速な静的出力（Vite + React）」に厳格に準拠する。
Core レイヤーに決定論的な階層レイアウト・影響波及パス計算エンジン `TraceabilityGraphBuilder` を配置し、Web UI レイヤーには純粋な React 19 + SVG コンポーネント `TraceabilityGraphView` を実装する。ノード配置は V字モデルの工程順序に応じたランク付き層別レイアウト（Ranked Stratum Layout）を採用し、エッジ描画にはスムーズな3次ベジェ曲線（Cubic Bezier Curve）を用いる。

### Structure
1. **Core 階層**: `src/core/graph/TraceabilityGraphBuilder.ts`
   - `buildGraph(nodes: DocNode[], options?: TraceGraphBuildOptions): TraceabilityGraphData`:
     - 全ノードを種類（kind）に応じて階層ランク（0: Need, 1: Actor/UseCase, 2: Requirement, 3: Specification/Design/Decision, 4: QualityAssurance/TestCase）へ割り当て。
     - 各ランク内でのノード順序整列（ID順・重要度順）および Y 座標（縦）／ X 座標（横）の間隔計算（`CARD_WIDTH = 220`, `CARD_HEIGHT = 80`, `X_GAP = 90`, `Y_GAP = 30`）。
     - `depends_on`, `verifies`, `actor_refs`, `requirement_refs`, `links` からのエッジ抽出と重複排除。
     - 選択ノードに基づく BFS / DFS による上流（Upstream）および下流（Downstream）ノード・エッジの到達可能性判定と `isHighlighted` / `isDimmed` フラグの算出。
2. **Web 階層**: `src/web/src/components/TraceabilityGraphView.tsx`
   - SVG コンテナと ViewBox 制御によるスムーズなズーム（0.2x〜2.5x）およびマウスドラッグによるパン機能。
   - 各ノードカードコンポーネント（種別バッジアイコン、ID、タイトル、ステータス、重要度/テスト工程、上流/下流接続数、クリックで選択・ハイライト、詳細ボタン）。
   - 有向エッジ（ベジェ曲線 `<path>`）、矢印マーカー（`<marker>`）、ハイライト時のストローク強調アニメーション/色分け。
   - コントロールツールバー（ズームイン/アウト、Fit to View、種別フィルターピル、ハイライトモード切替、ノード検索）。
   - ミニマップ（全体縮小プレビューと現在の表示矩形インジケーター）。
3. **App 統合**: `src/web/src/App.tsx`
   - タブナビゲーションに「トレーサビリティグラフ（`graph`）」を追加。
   - ノード選択時に既存の `selectedNodeId` と連動し、ドキュメント詳細インスペクターモーダルとシームレスに連携。

### Data Flow
```text
[DocNode[] (Report)]
        │
        ▼
[TraceabilityGraphBuilder.buildGraph(nodes, options)]
   ├── 1. 種別・検索フィルタリング
   ├── 2. 階層ランク別ノード配置（X, Y 座標決定）
   ├── 3. 有向エッジ抽出（depends_on, verifies, refs）
   └── 4. 選択ノードの影響波及（Upstream/Downstream）到達探索
        │
        ▼
[TraceabilityGraphData]
        │
        ▼
[TraceabilityGraphView (React SVG)]
   ├── SVG Canvas (Pan / Zoom Transform)
   ├── Edges Layer (<path d="M... C..." />)
   ├── Nodes Layer (<foreignObject> or <g> Card)
   └── UI Controls (Toolbar, Kind Pills, Fit Button)
        │ (Node Click / Open Detail)
        ▼
[Document Detail Modal (REQ-0004 / App.tsx)]
```

### Trade-offs
1. **外部 Force-directed 物理エンジン不採用の選択**:
   - D3-force や WebAssembly 物理シミュレータは自由な網状配置が可能である一方、実行コスト・バンドルサイズが肥大化し、毎回ノードの位置が変動して認知マップが崩れる欠点がある。
   - V字モデルに特化したランク付き階層配置（Ranked Stratum Layout）を採用することで、決定論的（毎回同じ位置に配置）かつ高速（100ノードを数ミリ秒で配置計算）であり、ソフトウェアエンジニアリングにおける「上流から下流への流れ」が直感的に理解しやすい。
2. **SVG vs HTML Canvas**:
   - 数千個のノードを描画する場合は Canvas/WebGL が有利だが、中〜大規模ドキュメント（数十〜数百ノード）では SVG の方がテキストの鮮明さ、CSS トランジション、DOM イベント（クリック、ホバー、アクセシビリティ）、レスポンシブ拡大において圧倒的に優れたユーザー体験を提供する。
