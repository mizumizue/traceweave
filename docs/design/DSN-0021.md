## Content

### Decision
単体テスト品質を「REQ/SPEC 充足度」と「実装カバレッジ」の2軸に分離する。`SufficiencyScorer` は `isTraceabilityTestCase` で unit を除外し、配点を内結35・外結/総合35・受入30（High）に再配分する。単体は `UnitCoverageAnalyzer` が `SourceFunctionScanner` + `CoverageReportLoader` で測定する。

### Structure
- `src/core/coverage/SourceFunctionScanner.ts`: `src/` の export 関数・クラスメソッド列挙
- `src/core/coverage/CoverageReportLoader.ts`: `coverage-summary.json` 読込・Node カバレッジ表パース
- `src/core/coverage/UnitCoverageAnalyzer.ts`: 関数テスト率・分岐率の集約
- `src/web/src/components/UnitCoverageView.tsx`: 専用タブ UI
- `scripts/run-test-suite.ts`: テスト実行時に `reports/coverage-summary.json` を生成

### Data Flow
1. `npm --prefix src test` → TAP レポート + カバレッジ表 → `coverage-summary.json`
2. `buildTraceWeaveReport` → `UnitCoverageAnalyzer.analyze` → `report.unitCoverage`
3. `BalanceAnalyzer.analyzeStrata` → unit 層は常に `code_coverage`（未生成時は missing）
4. `BalanceAnalyzer.diagnosePyramid` → strata 由来の counts を使用（単体 TC 文書件数は混在しない）
5. `MatrixBuilder.buildReport` → `summary.qualityAxes` に二軸サマリを出力
6. Web `/api/data` → `tab=unit` で `UnitCoverageView` 描画

### Trade-offs
- 関数インベントリは正規表現ベースの軽量スキャン（TypeScript AST 未使用）。複雑な再エクスポートは将来 AST 化の余地あり。
- カバレッジ未実行時は pending 表示とし、CI でテスト実行を前提とする。
