## Content

### Decision
単体テスト品質を「REQ/SPEC 充足度」と「実装カバレッジ」の2軸に分離する。`SufficiencyScorer` は `isTraceabilityTestCase` で unit を除外し、配点を内結35・外結/総合35・受入30（High）に再配分する。単体は `UnitCoverageAnalyzer` が `LcovParser` + `CoverageReportLoader` で測定する。カバレッジ計測自体は言語ツール（本リポジトリでは `c8`）に委譲する（ADR-0008）。

### Structure
- `src/core/coverage/LcovParser.ts`: `reports/lcov.info` のパースと `CoverageSummary` 正規化
- `src/core/coverage/CoverageReportLoader.ts`: `coverage-summary.json` 読込
- `src/core/coverage/CoverageDetailBuilder.ts`: LCOV 行・分岐データからファイル詳細 JSON を生成
- `src/core/coverage/UnitCoverageAnalyzer.ts`: 関数・分岐・行カバレッジの集約
- `scripts/build-coverage-artifacts.ts`: LCOV → `coverage-summary.json` + `coverage-files/`
- `src/web/src/components/UnitCoverageView.tsx`: 専用タブ UI

### Data Flow
1. `npm --prefix src run test:coverage` → `c8` がテスト実行 + `reports/lcov.info` 生成 → `build-coverage-artifacts` が正規化
2. `buildTraceWeaveReport` → `UnitCoverageAnalyzer.analyze` → `report.unitCoverage`
3. `BalanceAnalyzer.analyzeStrata` → unit 層は常に `code_coverage`（未生成時は missing）
4. `BalanceAnalyzer.diagnosePyramid` → strata 由来の counts を使用（単体 TC 文書件数は混在しない）
5. `MatrixBuilder.buildReport` → `summary.qualityAxes` に二軸サマリを出力
6. Web `/api/data` → `tab=unit` で `UnitCoverageView` 描画

### Trade-offs
- LCOV は言語横断の共通フォーマットだが、関数メタデータの粒度はツール依存。未テスト関数一覧は LCOV の FN/FNDA レコードに依存する。
- カバレッジ未実行時は pending 表示とし、CI または開発者が `test:coverage` を明示実行する前提とする。
