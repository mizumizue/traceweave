## Content

### Decision
MCP サーバーは `src/mcp/server.ts` に単一モジュールとして配置し、`@modelcontextprotocol/sdk` の `Server` + `StdioServerTransport` で stdio JSON-RPC を処理する。ドメイン計算は `src/application/` および `src/core/` を直接呼び出し、MCP 層にビジネスロジックを持たない。

### Structure
- `src/mcp/server.ts`: `startMcpServer(docsDir)` — ツール登録とハンドラ
- `src/cli/index.ts`: `mcp` サブコマンド — docs 解決後にサーバー起動
- 依存: `buildTraceWeaveReport`, `checkDocs`（既存 Application サービス）

### Data Flow
1. CLI `mcp` が `resolveDocsDir` で文書ルートを決定。
2. `startMcpServer` が stdio 接続を待受。
3. `CallTool` 受信時、ツール名に応じて Application を呼び出し、結果を `JSON.stringify` して `content[].text` に格納。
4. 要件未検出時は `isError: true` と構造化 JSON を返却（プレーンテキストのみの応答は禁止）。

### Trade-offs
- メリット: コアと同一ロジックを共有し、CLI/Web/MCP の結果不整合を防ぐ。オプション起動のためコア依存を増やさない。
- デメリット: stdio のみのためリモート MCP プロキシには別アダプタが必要。ツール数は最小 4 件に抑え、過剰な API 表面を避ける。
