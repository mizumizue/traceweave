## Content

### Decision
`SubjectContext` の解決を `src/application/resolve-subject-context.ts` に単一モジュールとして集約し、`buildTraceWeaveReport` 実行時に一度だけ解決して `TraceWeaveReport.subject` に付与する。`adopt-project/probe.ts` の `package.json` / ディレクトリ名解決ロジックは共有ヘルパーへ抽出し、adopt とランタイムで同一の名前解決を再利用する（`SPEC-0025` の解決順 3〜5）。

### Structure
- `src/core/models/types.ts`: `SubjectContext` 型と `TraceWeaveReport.subject` フィールド追加
- `src/application/resolve-subject-context.ts`: `resolveSubjectContext(options)` — 解決順・フォールバック実装
- `src/application/build-report.ts`: レポート構築末尾で `subject` を付与
- `src/infrastructure/reporting/MarkdownReporter.ts` / `ConsoleReporter.ts`: 先頭行に `displayName` を反映
- `src/web/src/components/Header.tsx`: ブランド行に `for {displayName}` を表示
- `src/web/index.html` の初期タイトルは汎用のまま、データ取得後に `document.title` を更新
- `src/cli/index.ts`: `serve` 起動メッセージに `displayName` を含める。グローバル `--subject` オプションを追加
- `src/mcp/tool-handlers.ts`: `get_traceability_summary` の返却 JSON に `subject` を同梱

### Data Flow
1. CLI または `serve` がリポジトリルートと任意の `--subject` / 環境変数を `resolveSubjectContext` に渡す。
2. 解決器が `.traceweave/config.json` → `package.json` → ディレクトリ名の順で `displayName` を決定する。
3. `buildTraceWeaveReport` がグラフ・マトリクス構築後、`report.subject` を設定する。
4. Web は `/api/data` または `data.json` から `report.subject.displayName` を読み、ヘッダーと `document.title` を更新する。
5. マークダウン・コンソールレポーターおよび MCP 要約は同一 `subject` を参照する。

### Trade-offs
- メリット: 表示の正本が `TraceWeaveReport` に一元化され、Web / CLI / MCP / エクスポートの不整合を防ぐ。adopt 時の probe と解決ロジックを共有できる。
- デメリット: `.traceweave/config.json` が新規の設定表面になる。モノレポ複数アプリは別 NEED で対応が必要。
- 代替案（却下）: UI だけで `package.json` を再読み込みする案は、静的 `data.json` や MCP と乖離するため却下。
