## Content

### Context
ADR-0004 において、リポジトリルートから Web 固有の開発資材（`index.html`, `vite.config.ts`, `tailwind.config.js`, `postcss.config.js`, `dist-web/`）を排除し `src/web/` へ集約した。しかし、リポジトリルート直下には依然として `package.json`、`package-lock.json`、`tsconfig.json` が残り、その結果として `node_modules/` および `dist/` がルートに展開されていた。lucid-memories プロジェクトではルート直下に `node_modules` や `dist` は一切存在せず、実装資産や依存関係はすべて `src/`（フロントエンドは `src/lucid_memories/web/frontend/`）に隔離され、ルート直下はガバナンス文書・全体構成マップ・実行用ラッパー（`bin/`）のみが最前面に並ぶクリーンな構成が徹底されている。TraceWeave においても、この指針に完全に準拠することが決定された。

### Decision
`package.json`、`package-lock.json`、`tsconfig.json`、`node_modules/`、および `dist/` を含むすべての実装・依存・生成物資産をリポジトリルートから撤去し、`src/` 配下に完全カプセル化する。

1. **パッケージ・ビルド設定の集約**:
   - `package.json`, `package-lock.json`, `tsconfig.json` を `src/` 直下へ移設。
   - `src/tsconfig.json` のコンパイル出力先を `src/dist` とし、Web バンドル出力先を `src/web/dist` とする。
2. **ルート実行ラッパー（`bin/traceweave`）の提供**:
   - lucid-memories の `bin/lucid-memories` と同様に、リポジトリルートに `bin/traceweave`（bash / cmd / ps1）を配置。
   - ラッパー内部で `NODE_PATH="$ROOT/src/node_modules"` を設定し、利用者がルートから透過的に CLI コマンドやタスクを実行可能とする。
3. **ルートの完全クリーン化**:
   - ルート直下の `node_modules/` および `dist/` を完全撤去。
   - `.gitignore` および `.cursorignore` を更新し、`src/node_modules/`、`src/dist/`、`src/web/dist/` を除外対象に設定。

### Consequences
- リポジトリルートから `node_modules/` の数千ファイルや `dist/` の生成物が完全に一掃され、製品概要・アーキテクチャ・開発者ガイド・ドキュメント・ラッパーのみが整然と並ぶ美しい構成が完成する。
- Node.js / TypeScript の実装・依存関係が `src/` 内で完全にカプセル化され、サブシステム境界と保守性が向上する。
- コマンド実行は `./bin/traceweave <command>` または `npm --prefix src <command>` でシンプルかつ直感的に行える。
