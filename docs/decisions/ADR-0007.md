## Content

### Context
TraceWeave は、V字モデルの要求〜テストトレーサビリティおよびテスト地層密度分析を自律的に提供する品質保証プラットフォームである。しかしこれまで、本リポジトリ自身の構造と異なる外部プロジェクト（既存の Web アプリ、API バックエンド、マイクロサービス、ライブラリ等）に対して TraceWeave を導入・適用するための標準スクリプト、Cursor エージェントスキル、および包括的なインストールガイドが存在しなかった。

外部プロジェクトへの適用にあたっては、以下の異なる 2 つの需要が存在する：
1. **既存資産を破壊せずに導入したい（解析・一時適用）**: 既存のディレクトリ構造やビルド設定に手を加えず、TraceWeave の仕様・品質分析に必要な `docs/` 構造と最小限の検証用設定をアドオン（オーバーレイ）し、即座に現状分析・可視化を行いたい。
2. **TraceWeave 想定の構成に完全移行したい（完全再構成）**: プロジェクト全体を TraceWeave が推奨するクリーンルート規約（ADR-0004, ADR-0005: ルート直下のガバナンス純化、`src/` への資材カプセル化、`bin/` 透過ラッパー配備、厳格な V字モデル文書体系）へ根本から再編成したい。

特に完全再構成はディレクトリ移動や設定書き換えを伴う破壊的な変更となるため、操作前の確実なバックアップと決定論的なロールバック手段の担保が必須要件となる。

### Decision
外部プロジェクトへの TraceWeave 適用エンジン（スクリプト `scripts/adopt-traceweave.ts` および CLI `traceweave adopt`）、AI エージェント用 Cursor スキル（`traceweave-adopt`）、ならびに包括的インストールガイド（`INSTALL_GUIDE.md`）を整備し、以下の原則に従って実装する。

1. **2つの導入モード（Dual Adoption Modes）**:
   - **解析・一時適用モード (`overlay` / `analyze`)**: 既存プロジェクトの既存資材（ソースコード、テスト、設定）を一切破壊せず、既存リポジトリのメタ情報（言語・フレームワーク・既存テストスイート・README）を収集・解析した上で、TraceWeave 準拠の `docs/` スケルトン（NEED, REQ, SPEC, DSN, ADR, QA, TC）および初期設定ファイルをアドオン配置する。
   - **完全再構成モード (`restructure`)**: 既存プロジェクトの構造を TraceWeave 標準のクリーンルート規約に沿って再編する。ルート直下のソースコードや開発設定を `src/` 配下へ移設・カプセル化し、ルートにはガバナンス文書と `bin/` 透過ラッパーを配備し、既存ドキュメントを `docs/` 体系へ体系的に移行する。
2. **破壊的変更に対する安全機構とバックアップ戦略（Safety & Backup Strategy）**:
   - 変更の実行前に、対象リポジトリの現在状態をタイムスタンプ付きバックアップディレクトリ（既定: `.traceweave-backup/<YYYYMMDD_HHMMSS>_<mode>/`）へ退避コピーする。
   - バックアップの正常完了を確認（Verify）するまで、いかなる変更処理も開始しない。
   - 自動生成されたマニフェスト（`backup-manifest.json`）に基づき、ワンコマンド（`--rollback <backupDir>`）で適用前の状態を完全に復元可能とする。
   - Git リポジトリ配下の場合は、未コミット変更（Dirty tree）の有無を事前にプローブし、作業続行の安全性を明示的に確認する。
3. **Cursor エージェントスキル（`writing-great-skills` 準拠）**:
   - モデル起動スキルとして `.cursor/skills/traceweave-adopt/SKILL.md` を配備。
   - 先導語（_probe_, _checkpoint_, _overlay_, _restructure_, _rollback_）を活用し、検証可能な完了基準で各ステップをガードする。
   - 人間の指示に応じて「解析・一時適用」と「完全再構成」の分岐を的確に案内・実行する。
4. **インストールガイドの整備**:
   - `INSTALL_GUIDE.md` をリポジトリルートに配置し、TraceWeave 自身のセットアップ、CLI ラッパーの動作確認、MCP 連携設定、および他プロジェクトへの適用手順を一元的に解説する。

### Consequences
- あらゆる外部プロジェクトに対して、ユーザーの目的に応じて「安全な非破壊お試し導入」と「本格的なクリーンルート完全再編」を選択的かつ決定論的に適用可能となる。
- 事前バックアップとマニフェストによるロールバック機構により、破壊的変更に伴うプロジェクト破損リスクが排除される。
- AI エージェント（Cursor）が外部プロジェクトの構造を診断した上で、迷わず一貫した手順で TraceWeave を配備・適用できるようになる。
