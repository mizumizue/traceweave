## Content

### Context
TraceWeave は単体カバレッジを Node `--experimental-test-coverage` の V8 JSON と正規表現ベースの関数スキャンで内製していた。`serve` 起動時にはテストスイートを自動実行して `coverage-summary.json` を生成していた。これは TypeScript 専用であり、各言語が既に持つ成熟したカバレッジツールを再実装している。`SYSTEM_OVERVIEW.md` でも CI パイプライン・テストランナー設定は Out-of-Scope である。

### Decision
1. **計測の委譲**: カバレッジの計測・インストルメンテーションは言語ごとの標準ツール（本リポジトリでは `c8` + Node test runner）に任せる。
2. **LCOV を境界契約に**: TraceWeave は `reports/lcov.info` を第一入力とし、正規化済み `reports/coverage-summary.json` および `reports/coverage-files/` を生成・消費する。
3. **テスト実行の分離**: `npm test` は `test-results.json` のみ生成する。カバレッジは `npm run test:coverage` で明示的に生成する。
4. **自動実行の廃止**: `ensureUnitCoverageReport` はアーティファクト存在確認のみ行い、テストスイートを起動しない。
5. **内製パーサの削除**: `V8CoverageAggregator`、`SourceFunctionScanner`、TAP カバレッジ表パースを廃止する。

### Consequences
- 多言語プロジェクトでは各言語ツールが LCOV（または将来 Cobertura 等）を出力し、TraceWeave は同一の正規化パイプラインで表示できる。
- カバレッジ未生成時は `pending` 表示のまま。利用者は `npm run test:coverage` を実行する必要がある。
- `serve` 単体ではカバレッジを自動生成しない。CI や開発者の明示的なカバレッジ実行が前提となる。
