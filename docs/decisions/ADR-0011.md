## Content

### Context
`tests/` 配下に UI 契約の静的解析・ソース読取・ビルド成果物検査が混在し、タイトル中の `TC-` 文字列だけで `reports/test-results.json` に結合されていた。ブラウザ DOM や受入シナリオを要する工程のオラクルが、プログラム的ハーネスで満たされたように見えるリスクがある。

### Decision
- **形式証跡（formal）**: ワークスペーススイートの `evidenceTier: formal`（既定）のみが `reports/test-results.json` へマージする。自動テストが TC の `execution_status` を更新するには、**テストタイトルが `TC-<STRATUM>-<NNNN>[-SS]:` で始まる**宣言行が必要（`formalTestCaseIdFromTitle`）。
- **補助ハーネス（supplementary）**: `evidenceTier: supplementary` のスイート（例: `tests/support/**`）は CI で実行してよいが、集約証跡には載せない。タイトルは `support:` 等のプレフィックスを用い、本文中の `TC-` 参照は証跡キーにならない。
- **Node 形式スイートの走査範囲**: 既定の formal Node スイートは `tests/support` と `tests/e2e` を走査対象から除外する。`testsDir` で明示したディレクトリのみ走査する supplementary スイートは除外規則を適用しない。
- **ブラウザ E2E**: ST / UAT で実ブラウザが要るオラクルは `tests/e2e/`（Playwright）を **formal** スイートとして追加する。公開 UI 契約の単体検証は `tests/core/` に残し、DOM 描画の正本は E2E に委ねる。
- **スキップ**: ローカルでブラウザ未導入の場合は `TW_SKIP_E2E=1` で E2E スイートのみスキップ可能（証跡は更新されない）。

### Consequences
- `.traceweave/config.json` は `node` / `support` / `e2e` / `newman-api` の複数スイートを定義する。
- `parseTapTestReport` と Playwright JSON 変換は title-prefix 規則のみを採用する。
- `test-writing-guidelines` と `traceweave-verification-tiers` スキルが配置・命名の運用正本となる。
