## Content

### Context
テストケース文書 ID が時系列連番（`TC-0001` …）のみであり、単体・内結・外結などの工程が ID から読み取れない。実行証跡は `TC-xxxx` キーで結合し、工程は `test_level` フロントマターが正本である。

### Decision
- テストケース ID 形式を **`TC-<STRATUM>-<NNNN>`** とする。`<STRATUM>` は `UT` | `ITa` | `ITb` | `ST` | `UAT`。`<NNNN>` は **当該層内の 4 桁連番**（層ごとに 0001 から採番）。
- `test_level` フロントマターを **残し正本とする**。`validateDocs` で ID のストラタムと `test_level` の不一致をエラーとする。
- ワークスペースの実行スイート ID は工程を表さない（SPEC-0028）。工程は TC 文書と実行レポートの TC キーで表す。
- 既存 dogfood 63 件は一括移行し、対応表を `scripts/migrate-tc-id-map.json` に残す。

### Consequences
- TAP / Newman / fragment の TC 抽出正規表現を新形式に更新する。
- 採用キットのスターター TC は `TC-UT-0001` 形式を用いる。
- 文書に存在しない未知 ID（API  negative テスト）は `TC-UT-9999` 等の有効形式かつ未登録 ID を用いる。
