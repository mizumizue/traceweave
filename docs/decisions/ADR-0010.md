## Content

### Context
テストケース文書に複数の独立シナリオが同居すると、トレーサビリティのオラクルが曖昧になる。分割時に当該層の末尾連番だけを使うと、元ケースと派生ケースが ID 上離れ、仕様書・ダッシュボード上の近接性が失われる。

### Decision
- **原子性**: 1 件の `test_case` は **1 つの合否オラクル** を記述する。複数の独立シナリオは別文書に分割する。
- **新規採番（非分割）**: 当該ストラタムの未使用 4 桁連番 `TC-<STRATUM>-<NNNN>`（ADR-0009）。
- **分割採番（枝番）**: 分割子は **親と同じ `<NNNN>` を保持**し、2 桁枝番を付与する。**`TC-<STRATUM>-<NNNN>-<SS>`**（`<SS>` は `01` … `99`）。例: `TC-ITb-0001` を 3 分割 → `TC-ITb-0001-01`, `TC-ITb-0001-02`, `TC-ITb-0001-03`。同一 `<NNNN>` 内で枝番を連番採用し、欠番の詰め直しはしない。
- **親の退役**: 分割元 `TC-<STRATUM>-<NNNN>`（枝番なし）は `status: deprecated` または `superseded` とし、**`supersedes`** に子 ID 一覧を列挙する。親 ID を分割子のオラクルとして残さない。
- **系譜**: 子は **`derived_from`** に親 ID（枝番なしの元 ID）を記録する。実行証跡キーは子 ID を用い、親 ID の証跡を暗黙継承しない。
- **層末尾連番との使い分け**: 親番号と無関係な新規 TC は引き続き `<NNNN>` のみ。枝番は **分割に限定** する。
- **移行表**: 分割時は `scripts/migrate-tc-id-map.json` に `from` / `to` / `reason` を追記する。

### Consequences
- `TEST_CASE_ID_PATTERN` および TAP 抽出は枝番付き ID を正本として扱う（DSN-0024 / `testCaseId.ts`）。
- `validateDocs` は `supersedes` / `derived_from` の参照整合と、退役親の `supersedes` 必須を検査する。
- レビュー指示の標準文は「親 `TC-ITb-0001` を deprecated、`supersedes` に `TC-ITb-0001-01` … を列挙」。
