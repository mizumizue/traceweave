## Content

### Context
TraceWeave の開発初期において、Web ダッシュボード用の資材（`index.html`, `vite.config.ts`, `tailwind.config.js`, `postcss.config.js`）がリポジトリルートに直接配置され、またビルド生成物もルート直下の `dist-web/` に出力されていた。これにより、リポジトリルートが散乱し、TypeScript パッケージ全体としての責務境界が曖昧になっていた。lucid-memories プロジェクト（ADR-0008, README.md）では「ルート直下は製品のガバナンス・決め事・全体構成マップを最前面に配置し、実装コードは src/ 配下に集約する」という厳格な指針が採られており、これに従ってリポジトリ構造を洗練させる必要が生じた。

### Decision
Web フロントエンドに関連するすべての開発資材をリポジトリルートから撤去し、`src/web/` 配下に完全カプセル化する。Web ビルド成果物の出力先は後続の ADR-0005 で `src/web/dist/` に具体化し、ルート直下の `dist-web/` を廃止する。さらに、リポジトリルートには製品ガバナンス文書として `DEVELOPER_GUIDE.md` を配置し、文書駆動開発プロセスとクリーンルートの規約を明文化する。

### Consequences
- リポジトリルートから `index.html`, `vite.config.ts`, `tailwind.config.js`, `postcss.config.js`, `dist-web/` が完全に一掃され、製品概要・アーキテクチャ・開発者ガイド等の最重要ドキュメントと基本メタデータのみが最前面に並ぶ美しいリポジトリ構造が実現される。
- Web ダッシュボードの関心事（HTML・スタイル・ビルド設定・コンポーネント）が `src/web/` 内で自己完結し、他サブシステム（Core, CLI, MCP）との責務境界が明確になる。
- ビルド生成物の最終配置は後続の ADR-0005 で `src/`（Web は `src/web/dist/`）へ具体化され、ルート外へのカプセル化が維持される。
