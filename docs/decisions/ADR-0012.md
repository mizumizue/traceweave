## Content

### Context
`integration_internal`（ITa）以上の TC 本文に、クラス名・メソッド呼び出し・JSON プロパティ名など実装語彙が Preconditions / Steps / Expected Results に残り、QA 向け契約手順になっていない。`validateDocs` は当初 ITb 以上のみ警告で、lint 失敗に至らなかった。

### Decision
- **適用範囲**: `test_level` が `integration_internal` 以上の非退役 TC について、Preconditions / Steps / Expected Results を **interface fence** の機械検査対象とする（`tcInterfaceFence.ts`）。
- **違反の扱い**: `[tc-interface-fence]` は **errors** とし、`npm --prefix src run lint` を失敗させる（DSN-0024 改訂）。
- **Objective**: 検証対象の要約として実装名を含み得る。executable 三節は観測可能な振る舞い・契約 API のみ。
- **外結の例外**: `integration_external` 以上では、MCP ツール名（`` `get_*` `` / `` `check_*` ``）を外部契約として backtick 記述を許可する。
- **意味監査**: 正規表現で捕捉できない境界は `traceweave-test-case-review` / Subagent `traceweave-test-case-reviewer` が **contract-surface** で監査する。

### Consequences
- 既存 TC 文書は契約表現へ書き換え済みであることが lint 成功の前提。
- 新規・改訂 TC は authoring ルールとスキル step **sweep** で fence errors をゼロにしてからマージする。
