## Content

### Context
初期の検討において、Cursor などの AI エージェントとの連携を主軸に据える案があった。しかし、複数人の開発プロジェクトにおいて、チーム全員が Cursor や MCP を使用しているとは限らず、特定のエディタや個人の開発環境にプロダクトの主機能が密結合することは望ましくないという懸念が示された。

### Decision
TraceWeave のコアは「CLI ツールおよび Git ネイティブな静的 HTML 出力」とし、MCP サーバーは `traceweave mcp` というサブコマンドで起動可能なオプショナルな拡張機能（薄いラッパー）として位置づける。

### Consequences
- プロダクトのポータビリティが確保され、CI/CD パイプラインや非エンジニア（QA、PM）への成果物共有が阻害されない。
- Cursor などの AI エージェントを活用したい開発者は、必要に応じて `traceweave mcp` を起動して対話的に品質情報を取得できるという柔軟性を両立できる。
