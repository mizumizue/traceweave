## Content

### Objective
トレーサビリティグラフビルダー（`TraceabilityGraphBuilder`）が、パースされたドキュメントノード群から有向グラフデータを正しく構築し、工程順の階層ランク付けと座標算出を行い、循環参照を安全に処理した上で、選択ノードに対する上流（Upstream）および下流（Downstream）の影響波及パスを正確に探索・ハイライトでき、Web UI（`TraceabilityGraphView`）において原則All表示・各種別クリックによる非表示除外トグル・All復帰操作・下スクロール閲覧・全画面表示・全幅フィットが正常に機能することを検証する。

### Preconditions
- 各種別（NEED, ACT, UC, REQ, SPEC, DSN, ADR, QA, TC）の `DocNode` が供給され、`depends_on`, `verifies`, `links` 等の参照関係が設定されていること。

### Steps
1. テスト用のノード群（NEED-0001 <- REQ-0001 <- SPEC-0001 <- DSN-0001, TC-0001 verifies REQ-0001, SPEC-0001）を `TraceabilityGraphBuilder.buildGraph` に渡す。
2. 生成された視覚ノードの `rank`（階層ランク）が上流から下流へ順序付けられていること（NEED: 0, REQ: 2, SPEC: 3, TC: 4 等）を検証する。
3. 接続エッジの `source` と `target` が正しく構築され、重複エッジが排除されていることを検証する。
4. 特定のノード（例: SPEC-0001）を選択（`selectedNodeId: 'SPEC-0001'`）した際、上流ノード（REQ-0001, NEED-0001）および下流ノード（DSN-0001, TC-0001）が正確に `isHighlighted: true` となり、無関係なノードが `isDimmed: true` となることを検証する。
5. ハイライトモード（`upstream`, `downstream`）を指定した際、意図した方向のノードのみがハイライトされることを検証する。
6. 種別除外フィルター（`excludedKinds`）を適用した際、初期全表示状態から指定された種別（例: TC-0001 のみ除外）のノードとそれに接続するエッジが適切に非表示化され、他のノード群が表示維持されることを検証する。
7. Web UI コンポーネントおよび App 統合において、ズーム制御・下スクロール対応（`overflow-auto`）・Sticky列ヘッダー・全幅フィット・全画面トグル、および種別チップクリックによる非表示除外トグル・Allボタンによる全表示復帰が提供されていることを検証する。

### Expected Results
- 全てのノードに有効な `x`, `y`, `width`, `height`, `rank` が割り当てられ、ノード座標が NaN や無限大にならないこと。
- 上流および下流のトレースパス探索が誤りなくグラフエッジを辿り、期待されるノードのみがハイライトされること。
- 循環参照が存在する場合でも無限ループに陥らず安全に完了すること。
- 原則として全種別のノードが表示され、特定の Kind チップクリックでその種別のみが非表示となり、再度クリックまたは All ボタンクリックで正確に復帰すること。
- 下スクロールや全画面切替等の対話機能要素が正しく配置・統合されていること。

### Actual Results
- 単体テストおよび UI 結合テストにおいて全アサーションが成功し、レイアウト計算の決定性、エッジ抽出、上流・下流パスの探索精度、およびスクロール・表示機能の統合が確認された。
