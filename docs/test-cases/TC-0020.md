## Content

### Objective
Web ダッシュボードのヘッダーロゴがルートへのアンカーリンクとして機能し、クリック時に SPA の内部状態が初期ルート状態へリセットされ、URL のクエリパラメータがクリアされて履歴に追加されること、ならびに修飾キー押下時のブラウザ標準動作が担保されていることを検証する。

### Preconditions
- Web ダッシュボードのコンポーネント群（`Header.tsx`, `App.tsx`）が実装されていること。

### Steps
1. `Header.tsx` のソースコードを検査し、Logo 要素がアンカータグ（`<a>`）でマークアップされ、適切なルート `href`、アクセシビリティ属性、ホバースタイルが指定されていることを確認する。
2. `Header.tsx` がロゴクリック時のコールバックハンドラ（`onNavigateHome` 等）を受け取り、修飾キーの有無を適切にハンドリングしていることを確認する。
3. `App.tsx` において、ロゴクリック時にアクティブタブ、選択ノード、検索キーワード、および各種フィルタが初期状態へリセットされるロジックが組み込まれていることを確認する。
4. 自動テスト（`tests/web/header-logo-link.test.ts`）を実行し、静的構造およびロジックのアサーションが成功することを確認する。

### Expected Results
- ヘッダーロゴが `<a>` タグで構成され、ルートへのリンクとして機能すること。
- 通常クリック時に SPA 内で初期ルート（`matrix` タブ、ノード未選択、フィルタ解除）に復帰すること。
- 修飾キー付きクリック時にブラウザの標準遷移が妨げられないこと。

### Actual Results
- `tests/web/header-logo-link.test.ts` において全検証項目がパスし、REQ-0025 および SPEC-0020 の要件を完全に満たしていることが実測された。

### Evidence
- 自動テスト `tests/web/header-logo-link.test.ts` の合格ログおよび `npm run lint` の正常完了。
