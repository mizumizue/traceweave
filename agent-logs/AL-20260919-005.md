## Content

### Objective

**課題:** テストピラミッド画面に仕様書を載せると役割が混ざり、QA が手順・期待値を一覧でレビューしづらかった。単体はカバレッジ軸（REQ-0031）なのに TC 文書として並ぶ違和感もあった。旧 TC 番号は工程が読み取れない。

**対応:** TC を層プレフィックス ID に移行し、Web に「テスト仕様・結果」タブを新設。ITa〜UAT は表形式の全文レビュー＋詳細モーダル（パラメータ JSON 含む）、UT は同一タブ内のカバレッジビューに統合。コアに層別カタログ・充足判定・UC ロールアップを載せ、単体カバレッジ専用タブは廃止。

### Completion Criteria

- [x] `npm --prefix src run lint` 成功
- [x] `npm --prefix src test` 成功（175 tests）
- [x] テスト仕様・結果がピラミッドタブから分離
- [x] UT は仕様表に出さずカバレッジを同一タブで表示
- [x] 層別 TC ID と参照の整合

### Changes

**TC ID 移行とガバナンス** — `TC-00xx` を層プレフィックス ID へ置換し、検証・fixture・Postman・テストコードを追随。`testCaseId` ヘルパと移行スクリプトを追加し、UT の `verifies` は REQ/SPEC 禁止を validate で維持。

**層別カタログと充足** — `buildTestStratumCatalog`・readiness 判定・UC/FR 分類をレポートに載せ、マトリクス充足は UT をトレーサ対象外のまま維持。

**Web「テスト仕様・結果」** — 専用タブ、UT→UAT 工程切替、手順・期待値の表と詳細モーダル。ピラミッド層クリックは `testbooks` + `book=` へ。旧 `tab=unit` は互換リダイレクト。

### Outcome

内結以降の TC を工程ごとに QA レビューでき、単体品質は同じタブの UT でカバレッジのみ確認できる。REQ トレーサビリティと実装カバレッジの境界が UI でも REQ-0031 に沿って分かれる。
