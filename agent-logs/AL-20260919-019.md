## Content

### Objective

**課題:** テストコードに `TC-xxxx` を直書きするのは typo しやすく、エディタ補完も効かない。TraceWeave の形式証跡はタイトル先頭の TC 宣言行が正本のまま、開発体験だけを改善したい。

**対応:** `docs/test-cases` から TypeScript カタログを生成し、`formalTestTitle` と `TC_IDS` で宣言行を組み立てる。`--tc` 解決と governance lint でカタログの鮮度を担保する。

### Completion Criteria

- [x] `generate:tc-catalog` で `src/generated/traceweave-tc-ids.ts` を生成できる
- [x] `formalTestTitle` が ADR-0011 形式のタイトルを返す
- [x] `testFileDeclaresCase` が `formalTestTitle(TC_IDS.*)` 宣言行を認識する
- [x] governance lint がカタログ未更新を検出する
- [x] `npm --prefix src run lint` および `npm --prefix src test` が成功する

### Changes

**TC ID カタログ生成** — `tcIdCatalog.ts` と `generate-tc-id-catalog.ts` で TC 文書の id/title/status を走査し、`as const` の `TC_IDS` モジュールを出力する。エディタは通常の TypeScript 補完で TC を選べる。

**形式宣言行ヘルパ** — `formalTestTitle` で ID 検証と `TC-xxxx: 説明` の整形を一箇所に集約。証跡パイプラインはタイトル文字列の先頭規則のみを見る前提は維持。

**--tc と lint 連携** — `testFileDeclaresCase` をカタログ経由宣言行に対応。`run-governance-lint` にカタログ鮮度チェックを追加し、TC 文書変更後の取りこぼしを機械的に防ぐ。

### Outcome

テスト作者は `TC_IDS` の補完から `formalTestTitle` で `test(...)` を書ける。TraceWeave のダッシュボード結合と `npm test -- --tc` は従来と同じタイトル規則で動く。TC 文書を増減したら `generate:tc-catalog` を回す運用になる。
