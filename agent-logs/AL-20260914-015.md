## Content

### Objective

**課題:** TraceWeave の主要表面（Web、レポート、CLI 案内）がツール自身のブランドのみを示し、品質保証の対象アプリケーション名が伝わらない。複数リポジトリを並行運用すると、どのアプリのトレーサビリティを見ているか迷う。

**対応:** パスAとして NEED-0010 を起票し、観測可能な要件 REQ-0030、外部契約 SPEC-0025、内部設計 DSN-0020 へ 1:N 分解。既存 Web ダッシュボード契約（SPEC-0005/0020）へ subject 参照を配線する。

### Completion Criteria

- [x] NEED-0010 / REQ-0030 / SPEC-0025 / DSN-0020 を起票
- [x] SPEC-0005・SPEC-0020 に SPEC-0025 リンクと subject 表示契約を追記
- [x] `npm --prefix src run lint` が成功

### Changes

**要求・要件の起票。** NEED-0010 で「対象アプリの QA 文脈を常に識別したい」課題を定義し、REQ-0030 で Web ヘッダー・タイトル・レポート・プレビュー案内への一貫表示を観測成果として AC 化した。実装手段は REQ に書かず SPEC に委譲する。

**契約と設計の分離。** SPEC-0025 で SubjectContext スキーマ、解決順、各表面の表示フォーマットを ICD として固定。DSN-0020 で resolve-subject-context への集約と TraceWeaveReport.subject 伝播経路を設計した。

**既存仕様への配線。** SPEC-0005 のレポート入力に subject を追加し、SPEC-0020 のヘッダー契約に対象名行の配置を明記。リンクグラフでトレーサビリティを維持する。

### Outcome

実装前に「どのアプリ向け QA か」を全表面で揃える契約が文書化される。次の実装タスクは DSN-0020 に沿って subject 解決と表示伝播を追加できる。
