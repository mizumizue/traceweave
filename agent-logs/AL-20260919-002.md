### Objective

**課題:** テスト実行パスと証跡の場所がリポジトリごとに暗黙で、Web/API など複数エンジンを束ねた製品単位の充足度表示と整合していなかった。

**対応:** `.traceweave/config.json` をワークスペース正本にし、suite 実行結果を TC ID で集約マージする。ユースケース充足度の派生集計と CLI `test`、ラッパーの CLI 再ビルド、serve 結合テストの安定化を同一作業単位で揃える。

### Changes

ワークスペース層を追加し、上方向の `.traceweave` 探索、`TRACEWEAVE_WORKSPACE`、suite の `node-test-tap` / `fragment` / `aggregate`、fail-wins マージを実装した。レポート読込・docs 解決・カバレッジパスはワークスペース設定を優先する。

dogfooding 用 `.traceweave/config.json` を配置し、`run-test-suite` をワークスペースオーケストレーションに接続した。テスト開始前の `data.json` 準備と終了後の同期で TC-0028 の flake を防ぐ。

ユースケース充足度（REQ-0032 系）のスコアラ・レポート/UI 連携、CLI `test`、bin ラッパーの stale dist 再ビルド、serve の Vite スキップと HTTP 起動待ちを含め、製品として一連の QA 体験が通るようにした。

### Outcome

利用者は任意の cwd から `./bin/traceweave test` で設定済み suite を実行し、単一の `reports/test-results.json` に基づくダッシュボード・充足度を見られる。複数コードベースは config の suite 追加で表現し、表示は製品集約のまま維持される。
