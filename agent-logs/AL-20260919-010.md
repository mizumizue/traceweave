## Content

### Objective

**課題:** ADR-0010 で分割退役した親 TC が、ダッシュボードのテストブック・マトリクス・グラフ・文書カタログに残り、子ケースと二重にトレーサビリティへ載っていた。

**対応:** `isActiveTestCase` で退役親を一括除外し、グラフの `verifies` 登録・レポート `nodes`・ガバナンス（空 `verifies` 許可）を揃えた。

### Completion Criteria

- [x] 退役分割親がテストブック・マトリクス・グラフ・カタログに出ない
- [x] TraceGraph が退役親の `verifies` をエッジにしない
- [x] 退役親 TC 文書は `verifies: []` で lint 通過
- [x] `npm --prefix src run lint` 成功
- [x] `npm --prefix src test` 成功

### Changes

退役 TC の判定を `docStatus.isActiveTestCase` に集約し、TraceGraph・MatrixBuilder・buildTestStratumCatalog・DecisionsCatalogBuilder・TraceabilityGraphBuilder・SufficiencyScorer が同じ規則で親を無視するようにした。レポートの `nodes` も active TC のみを載せ、件数サマリーと整合させた。

`validateDocs` と `check-docs` は退役 `test_case` の空 `verifies` を許可し、分割親をオラクルとして残さない ADR-0010 の意図と一致させた。該当する退役親ドキュメントの `verifies` を空に整理した。

回帰用に `retired-test-case-visibility.test.ts` と validate-docs の退役ケースを追加し、結合テストのノード件数期待を「パース全件」から「ダッシュボード表示件数」に更新した。

### Outcome

利用者はダッシュボード上で分割子（`-01` 以降）だけを実行・追跡の対象として見られる。退役親は Markdown として残るが、充足度・マトリクス・グラフでは参照されない。
