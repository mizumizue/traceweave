## Content

### Objective

**課題:** 有効な REQ に対応する SPEC（`depends_on`）が無い「孤児 REQ」はトレーサビリティ上問題だが、起票途中で REQ だけ先に存在するケースも正当である。error で強制するとダミー SPEC の横行リスクがある。

**対応:** `validateDocs` に孤児 REQ 検出を追加し、DSN カバレッジ（error）とは分離して warning のみ出力する。lint は通過し、`traceweave check` では warnings に載せる。

### Completion Criteria

- [x] 有効 REQ に SPEC `depends_on` が無い場合 `warnings` に Coverage gap を出す
- [x] `passed` / lint exit code は error 無しで成功のまま
- [x] `check-docs` と governance lint が warnings を表示・伝播する
- [x] スキーマルール（`docs-document-schema.mdc`）を warning 仕様に更新
- [x] 孤児・カバー済みの単体テストを追加
- [x] `npm --prefix src run lint` および関連テスト成功

### Changes

**孤児 REQ 検出（warning）。** `validateDocs` の返却型に `warnings` を追加し、非 retired の全 REQ を走査。いずれの有効 SPEC も `depends_on` で参照していなければ Coverage gap を warnings に積む。`links` は精緻化の代わりにしない。

**出力経路の接続。** `run-governance-lint` と `validate-docs` CLI は PASS 後に黄字 WARN を表示。`checkDocs` は schema warnings を既存の warnings 配列へ `[schema]` プレフィックスでマージする。

**ガバナンス文書の同期。** `docs-document-schema.mdc` に SPEC カバレッジは警告である旨を追記し、DSN カバレッジが error のままであることを明示した。

### Outcome

REQ 先行起票中は CI を塞がず、孤児 REQ は lint / check の警告で可視化される。合意済み運用では warning を見て SPEC を足すタイミングを人間が判断できる。
