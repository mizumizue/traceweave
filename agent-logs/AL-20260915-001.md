## Content

### Objective

**課題:** MCP は 4 ツールと stdio だけで、CLI の matrix/catalog/decisions や文書リソース・プロンプト・HTTP トランスポート・Cursor 登録が未整備だった。

**対応:** MCP サーバーをモジュール分割し、7 ツール・リソース・プロンプト・Streamable HTTP を追加。リポ同梱と adopt 時の `.cursor/mcp.json` 生成を行う。

### Completion Criteria

- [x] ツール 7 件（matrix / catalog / decisions 追加）
- [x] Resources（`traceweave-doc://`）と Prompts（3 件）
- [x] `--transport http` で Streamable HTTP 起動
- [x] `.cursor/mcp.json` 同梱と adopt 自動生成
- [x] SPEC/REQ/DSN/TC 更新とテスト追加
- [x] `npm --prefix src run lint` および `npm --prefix src test` 成功

### Changes

**MCP サーバー拡張**  
`create-server.ts` で tools / resources / prompts を一元登録。`tool-handlers` に CLI 相当の 3 ツールを追加。`resource-handlers` と `prompt-handlers` で V字文書と再利用プロンプトを公開。`http-transport.ts` で stateless Streamable HTTP（`POST /mcp`）を提供。

**CLI と adopt 連携**  
`mcp` サブコマンドに `--transport` / `--host` / `--port` を追加。adopt overlay が未存在時のみ `.cursor/mcp.json` を生成。本リポにも開発用 `mcp.json` を配置。

**文書とテスト**  
SPEC-0023・REQ-0029・DSN-0019 を拡張し TC-0061 を新設。MCP / adopt / catalog 統合テストを更新。

### Outcome

Cursor や他 MCP クライアントから、トレーサビリティ分析・文書参照・標準プロンプトを一括利用できる。adopt したプロジェクトは MCP 設定例が自動で入り、HTTP トランスポートでリモート接続も可能になる。
