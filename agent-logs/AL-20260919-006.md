## Content

### Objective

**課題:** テストケース文書が自動化前提で書かれがちで、範囲が広い TC を分割するとき ID が層末尾連番だけだと親子が一覧上離れる。

**対応:** V字文書（REQ/SPEC/ADR/DSN）で契約観点・原子性・系譜を定義し、分割は `TC-<層>-<NNNN>-<SS>` 枝番を正本にする。`validateDocs` の fence 警告とレビュースキル／Subagent で運用を固定する。

### Changes

**文書セット** — TC を QA 向けインターフェース仕様と分割系譜（`supersedes` / `derived_from`）として ADR-0010 で固定。REQ-0034 と SPEC-0029 で受入と fence。DSN-0024 で検証実装の置き場を明示した。

**ID 契約** — 分割子は親と同じ 4 桁に `-01..99` を付与。非分割の新規のみ層内連番。ADR-0009 と SPEC-0028 の TAP 記述を追随した。

**機械検査** — 外結以上の Steps 等に実装語彙がある既存 TC は `[tc-interface-fence]` 警告（22 件）。退役親の `supersedes` 欠落は error。

**レビュー導線** — TC-REVIEW-CHECKS、authoring ルール、読み取り専用 Subagent で SPLIT 指示と contract-surface を標準化した。

### Outcome

レビューと lint が「分割は枝番」「本文は観測可能な振る舞い」を同じ語彙で扱える。既存 ITb 文書のリライトは警告リストが backlog になる。
