## Content

### Objective

**課題:** テスト実行・ adopt ・レポート出力の入口がシェルラッパー、ルート scripts、CLI、bin の複数経路に分散しており、HtmlReporter などダッシュボードと重複する CLI フォールバックも残っていた。

**対応:** 単一の npm / TypeScript 経路に寄せ、 adopt モジュールを CLI 正本に統合し、静的 HTML レポートと冗長ラッパーを削除してドキュメントと SPEC を現行契約に合わせる。

### Completion Criteria

- [x] `npm --prefix src run lint` が成功する
- [x] `npm --prefix src test` が成功する
- [x] 作業変更を AL ログと同一コミットに含める

### Changes

**Summary — テスト実行の単一路線化**

`scripts/test.sh` / `test.cmd` / `test.ps1` を廃止し、README と DEVELOPER_GUIDE の手順を `npm --prefix src test`（内部で `run-test-suite.ts`）に統一した。`scripts/lib/repo-root.ts` と scripts 用 `package.json` / `tsconfig.json` でルート解決と tsx 実行を安定化させ、`test:raw` など二重入口を package.json から取り除いた。

**Summary — adopt エンジンの CLI 正本化**

ルート `scripts/adopt-traceweave.ts` と単体 `adopt-project.ts` をやめ、`src/application/adopt-project/` 配下のモジュール分割を CLI とテストが直接参照する形にした。ADR-0007 の記述から廃止スクリプト名を除き、導入フローの正本を `traceweave adopt` に揃えた。

**Summary — レポート出力と bin ラッパーの簡素化**

CLI の `report --format html` と `HtmlReporter` を削除し、HTML 表示は Web ダッシュボード生成（`traceweave build`）に委譲する旨を SPEC-0010 に反映した。円形ゲージ SVG の契約は `render-circular-gauge-svg.test.ts` に移した。bin ラッパーから初回 `npm install` 自動実行を外し、CLI 側の依存確保に集約した。

**Summary — ダッシュボード同期と小さな共通化**

`sync-dashboard-artifacts.ts` でテスト後の `data.json` と coverage-files 同期を切り出し、`isRetiredDocStatus` と `emptyPhaseCounts` の重複定義を core に寄せた。

### Outcome

開発者はテストと品質チェックを `npm --prefix src test` / `lint` で一貫して実行でき、 adopt は CLI のみが正本になる。CLI 静的 HTML レポートはなくなり、可視化はビルド済みダッシュボードが担う。
