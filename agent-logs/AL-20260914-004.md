## Content

### Objective

**課題:** 充足度スコアが TC 文書の存在件数で加算されており、「文書がある」ことと「テストが通った」ことが混同されていた。未実行・失敗の TC でもスコアが水増しされ、品質の実態を反映できなかった。

**対応:** スコアリング入力を実行ステータス `passed` の TC に限定し、文書件数（`documentedPhaseCounts`）と実行件数を別集計する。REQ/SPEC/DSN/QA に契約を明記し、TC-0038 で検証する。

### Completion Criteria

- [x] SufficiencyScorer が passed のみをスコア加算、文書/実行を別集計
- [x] BalanceAnalyzer が実行合格ベースの地層密度と文書のみ警告を出力
- [x] MatrixBuilder サマリーに passed/pending/failed 件数を追加
- [x] REQ/SPEC/DSN/QA/TC-0038 を契約に整合
- [x] コア単体・結合テストを追加・更新
- [x] lint / test 成功
