## Content

### Objective

**課題:** `### Title` 直後に空行がある Markdown 文書で、旧 regex ベースのセクション抽出が本文を空として扱い、キャッシュ経由で解析結果が壊れるバグが別リポで発見されていた。

**対応:** 見出し分割方式へ置き換え、空セクションだけのキャッシュエントリを無効化するガードを追加し、回帰テストで取り込んだ。

### Completion Criteria

- [x] DocParser が見出し直後空行パターンで正しく sections を抽出する
- [x] SQLiteCache が壊れたセクションキャッシュを再解析へフォールバックする
- [x] 回帰テストが追加されている
- [x] `npm --prefix src run lint` と `npm --prefix src test` が成功する

### Changes

**DocParser:** `headingRegex` の lookahead 方式を `split(/^### /m)` ベースに変更。見出し直後の空行で本文が切り捨てられないようにした。

**SQLiteCache:** sections がすべて空だが raw content に `### ` が含まれるキャッシュを invalid として null を返し、再パースを促す。

**テスト:** 見出し直後空行の fixture で sections 抽出を検証する回帰テストを追加。

### Outcome

V字モデル文書で見出しと本文の間に空行がある場合でも、トレーサビリティ解析が正しいセクション内容を返す。過去の壊れたキャッシュは自動的に再構築される。
