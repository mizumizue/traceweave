## Content

### Objective

**課題:** シムリンクや npm link で TraceWeave CLI を動かすと、`subject` が CLI インストール先（traceweave 本体）から解決され、adopt 先リポジトリ名がヘッダーに出ない。

**対応:** `docs/` の親をホストプロジェクトルートとして解決する `resolveProjectLayout` を導入し、`resolveDocsDir` は cwd の `docs/` を優先する。

### Completion Criteria

- [x] 外部 docs 指定時に subject がホスト `package.json` から解決される
- [x] `buildWebDashboard` 向け CLI 型エラー修正
- [x] テスト追加・build:cli / npm test 成功

### Changes

**プロジェクトレイアウト解決**  
`resolveProjectLayout` で docsDir の親を projectRoot に採用。`buildTraceWeaveReport` が adopt 先の `.traceweave/config.json` と package 名を参照できるようにした。

**docs 探索順**  
`resolveDocsDir` で `process.cwd()/docs` を CLI パッケージ内 docs より先に探索し、別リポ cwd 実行時に本体 docs を誤参照しないようにした。

**CLI 型修正**  
`getReportBuildOptions` の戻り型を `docsDir: string` 必須にし、`build` コマンドの tsc エラーを解消した。

### Outcome

lucid-memories 等の adopt 先で `serve` 実行時、ヘッダーと起動ログにホストアプリ名（例: lucid-memories）が表示される。
