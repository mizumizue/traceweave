## Content

### Objective

**課題:** ダッシュボードを `serve` するだけでは `reports/coverage-summary.json` が無く単体カバレッジが pending のままになる。また前回の serve がポートを占有していると手動 kill が必要だった。

**対応:** serve 起動前にカバレッジサマリーを ensure し、指定ポートの LISTEN プロセスを reclaim してからサーバーを立ち上げる。

### Completion Criteria

- [x] `coverage-summary.json` 欠落時に serve がテストスイートを実行して生成する
- [x] ポート専有時に先行 PID を終了してから listen する（DSN-0003 / SPEC-0004）
- [x] TC-0033 の reclaim テストを追加する
- [x] `npm --prefix src run lint` および `npm --prefix src test` が成功する

### Changes

**ensureUnitCoverageReport の追加**

serve 起動直前に `reports/coverage-summary.json` の有無を確認し、無ければ既存 `run-test-suite.ts` を実行して生成する。テスト失敗時もカバレッジファイルが書ければ available 表示に進める。

**PortManager.reclaimPort の実装**

Windows は netstat/taskkill、POSIX は lsof/kill で LISTEN PID を検出・終了し、ポート解放をポーリングする。CLI serve は競合エラー終了の代わりに reclaim を呼ぶ。

**テスト追加**

`ensure-unit-coverage.test.ts` と `port-manager.test.ts` に present/unavailable および reclaim 成功ケースを追加した。

### Outcome

利用者は `traceweave serve` だけで単体カバレッジ付きダッシュボードを開け、前回 serve が残っていても自動で置き換わる。初回または reports 削除直後はテスト実行分の待ち時間が入る。
