## Content

### Objective
**課題:** `serve` 起動時に実装網羅率が pending のまま残ることがある。ポート占有で再起動が失敗する。マトリクスとグラフが別タブでトレーサビリティ導線が分断されていた。
**対応:** カバレッジ未生成時の自動テスト実行、先行リスナーのポート解放、トレーサビリティタブ内のマトリクス/グラフ切替を追加する。

### Completion Criteria
- [x] `ensureUnitCoverageReport` が serve 前に coverage-summary を用意する
- [x] `PortManager.reclaimPort` が専有ポートを解放して serve を再開可能にする
- [x] URL 状態を `tab=traceability` + `view=matrix|graph` に統合（レガシー互換）
- [x] lint / test 成功

### Changes
**serve 起動フロー.** `ensure-unit-coverage.ts` を追加し、`traceweave serve` がレポート欠落時にテストスイートを実行して `reports/coverage-summary.json` を生成する。`PortManager.reclaimPort` で Windows/Unix 双方の LISTEN プロセスを終了してからポートを再利用する。

**Web ナビゲーション.** マトリクスとグラフを `traceability` タブに統合し、`TraceabilityViewToggle` で切替。`urlState` は `?tab=matrix|graph` を `tab=traceability&view=...` に正規化し、旧 URL も読み取れる。

### Outcome
`serve` 再起動がポート競合で止まりにくくなり、ダッシュボードは起動時点で実装網羅率を表示できる。トレーサビリティのマトリクスとグラフは同一タブ内で切り替え可能。
