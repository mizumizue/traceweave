## Content

### Objective

**課題:** リポジトリ全体の ponytail-audit で、SQLite ネイティブ依存、ポート強制解放、TAP ストリーム手パース、未使用 API など過剰実装が ~900 行以上を占めていた。

**対応:** 最高レバレッジ項目（wave 1）を一括削減。`better-sqlite3` を JSON 永続化の `DocMtimeCache` に置換し、`PortManager` の PID キルスタックを削除、`run-test-suite` を TAP ファイル一括パースに簡素化、死蔵エクスポートと薄いラッパーを除去した。

### Completion Criteria

- [x] `SQLiteCache` / `better-sqlite3` を削除し `DocMtimeCache` で同等の mtime キャッシュを提供
- [x] `PortManager` を `isPortAvailable` のみに縮小、`serve` はポート占有時に即失敗
- [x] `run-test-suite.ts` のストリーミング TAP パーサーをファイル一括パースに置換
- [x] 死蔵 API（`ensureWebDashboardBuilt`、`prepareServeDashboard`、`isExecutable` 等）を削除
- [x] `npm --prefix src run lint` 成功
- [x] `npm --prefix src test` 成功（143 tests）

### Changes

**DocMtimeCache への移行。** `better-sqlite3` と 134 行の `SQLiteCache` を、インメモリ `Map` とオプション JSON 永続化（`src/.cache/traceweave-cache.json`）の `DocMtimeCache` に置換。`DocParser`・`build-report`・関連テストを更新し、ネイティブ依存を 1 件削除した。

**PortManager 簡素化。** netstat/lsof/taskkill による PID 強制終了スタック（~120 行）を削除。`traceweave serve` はポート使用中ならエラー終了し、`--restart` オプションも廃止。利用者は明示的にプロセスを止めるか別ポートを指定する。

**テストランナー縮小。** dual reporter（spec→stdout、tap→temp file）で TAP を一括パースする方式に変更。チャンク単位の手書き状態機械（~110 行）を除去し、TC-ID 抽出ロジックは `parseTapReport` に集約。

**死蔵コード・薄ラッパー削除。** `fs-utils.ts`（`fs.cpSync` で代替）、`prepareServeDashboard`、`ensureWebDashboardBuilt`、`TraceGraph.getNeeds`、`TestRunnerRegistry` の未使用メソッドを削除。`runTestAsync` は `Promise.race` に簡素化。

### Outcome

TraceWeave のインストールがネイティブビルド不要になり、依存とコード量が大幅に減る。`serve` のポート競合は以前の自動キルではなく明示的なエラーで扱われる。テスト実行の見た目（spec 出力）とレポート生成は維持される。

### Improvements

**Before:** `better-sqlite3` 必須、PortManager 161 行、TAP ストリーム手パース 110 行超。

**After:** 純 JS キャッシュ、PortManager 16 行、TAP ファイル一括パース ~50 行。差分 net ~880 行削除。

**How Measured:** `git diff --stat`、package.json 依存差分、`npm test` 143/143 pass。
