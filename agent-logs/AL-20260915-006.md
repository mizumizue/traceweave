## Content

### Objective

**課題:** adopt は V字スケルトンとスキーマ検証までしか担保せず、TC 中身・テスト命名・CI・意味監査はプロジェクト側が自力で揃える必要があった。

**対応:** adopt 時に品質キット（AC 対応 TC、セットアップガイド、レポート取得スクリプト、CI テンプレ、レビュースキル）を自動配備し、`adopt-quality-check` で機械的ゲートを追加する。

### Completion Criteria

- [x] overlay/restructure adopt で品質キットファイルが注入される
- [x] TC-0001/0002 が REQ AC-001/AC-002 に対応する
- [x] `traceweave adopt-quality-check` CLI が追加される
- [x] traceweave-adopt スキルと INSTALL_GUIDE が更新される
- [x] adopt 関連テストが PASS

### Changes

**品質キット生成。** `quality-kit.ts` で ADOPT_QUALITY_SETUP、test-results キャプチャ script、GitHub Actions テンプレ、test-case-review スキルと test-writing ルールを adopt 先へ配備。スターター TC を AC 単位に分割し QA 証跡を reports に接続。

**機械的ゲート。** `quality-check.ts` と `adopt-quality-check` コマンドで必須ファイル・AC 参照・テストコード命名の有無を検査。ボイラープレート残存は warning。

**ドキュメント連携。** traceweave-adopt スキルの verify 手順と INSTALL_GUIDE 5.5 に導入後チェックリストを追記。

### Outcome

外部プロジェクト adopt 直後から、TC 品質・CI・レポート出力の足場が揃う。意味監査はスキル配備と手順書で促し、配備漏れは CLI で即検知できる。
