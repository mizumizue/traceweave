## Content

### Objective

**課題:** 単体テストを REQ/SPEC の `verifies` に紐づけて充足度スコアに加算していたが、関数単位の検証は仕様トレーサビリティとは別軸であり、紐づけの意味が薄い。単体品質は関数テスト率・分岐網羅率で測るべき。

**対応:** トレーサビリティ充足度（内結〜受入）と単体実装カバレッジを分離。V8 カバレッジ集約・専用 Web タブ・ガバナンスルール（unit TC は REQ/SPEC verifies 禁止）を一括導入。

### Completion Criteria

- [x] REQ-0031 / SPEC-0026 / DSN-0021 起票
- [x] SufficiencyScorer が unit をトレーサビリティスコアから除外し配点再配分
- [x] UnitCoverageAnalyzer と `reports/coverage-summary.json` 生成
- [x] Web「単体カバレッジ」タブ追加
- [x] 既存 unit TC の verifies 整理とテスト・lint 合格

### Changes

単体とトレーサビリティの二軸分離をコアから UI まで通した。`SufficiencyScorer` は unit TC を集計対象外にし、High 要件の配点を内結・外結/総合・受入へ再配分。マトリクス表示もトレーサビリティ対象 TC のみに限定した。

`src/core/coverage/` にソース関数スキャン、V8 JSON 集約、レポート結合の分析器を追加。`run-test-suite.ts` はテスト実行後に `coverage-summary.json` を自動生成する。ダッシュボードは `tab=unit` で関数率・分岐率・モジュール別一覧を表示し、ピラミッドの単体層は code coverage メトリクスを使う。

ガバナンス面では unit TC の `verifies` に REQ/SPEC を禁止し、既存 17 件の unit TC を `verifies: []` に更新。関連テスト・フィクスチャの期待スコアを新ルールに合わせて修正した。

### Outcome

利用者は REQ 充足度と単体実装品質を別タブ・別指標で観測できる。単体は `npm test` 後のカバレッジサマリーに基づき、内結以降は従来どおり TC トレーサビリティで評価される。
