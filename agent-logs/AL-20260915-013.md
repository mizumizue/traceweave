## Content

### Objective
**課題:** 「充足度」が REQ/SPEC トレーサビリティのみを指す一方、ピラミッド診断や地層集計に単体 TC 文書件数が混在し、全体品質を一つのゲージで示していた。
**対応:** 契約軸（ITa〜UAT）と実装軸（関数・分岐カバレッジ）を型と UI で分離し、BalanceAnalyzer の単体層を常に code_coverage 由来に統一する。

### Completion Criteria
- [x] REQ-0031 / SPEC-0026 / DSN-0021 をコミット可能な状態に整備
- [x] REQ-0002 を二軸モデルに改訂（単体を契約充足から除外）
- [x] diagnosePyramid が strata ベースの counts を使用（単体 TC 文書で上書きしない）
- [x] analyzeStrata の unit 層が traceability フォールバックしない
- [x] summary.qualityAxes とダッシュボード二ゲージ
- [x] lint / test 成功

### Changes
**BalanceAnalyzer の軸分離.** `tallyTraceabilityPhases` で unit を除外し、単体層は常に `UnitCoverageAnalyzer` 由来。`diagnosePyramid` は strata counts のみ使用。SPEC 未検証警告もトレーサビリティ TC のみを対象にした。

**レポートと UI の二軸サマリ.** `QualityAxesSummary` を `TraceWeaveReport.summary` に追加。ヘッダーを「契約充足度」「実装網羅率」の二ゲージに変更。CLI コンソール出力も同様。

**文書整合.** REQ-0002、TC-0002/0038/0025 を二軸・単体除外に合わせて改訂。既存 SufficiencyScorer の unit 除外ロジックと REQ-0031 セットを正式化。

### Outcome
利用者はダッシュボードで契約が検証されているかと実装が網羅されているかを別ゲージで見られる。ピラミッドと地層密度の単体層はコードカバレッジのみを反映し、単体 TC 文書の件数で歪まなくなる。
