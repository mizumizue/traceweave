## Content

### Objective

**課題:** `resolveTestFilesForCase` は `test('TC-xxxx:` 行を静的解析するが、test-writing-guidelines には角括弧付き例しかなく、機械連携の必須形が文書化されていなかった。

**対応:** 機械連携向け TC 宣言セクションをルールに追加し、adopt 品質キットのセットアップ手順から参照する。

### Completion Criteria

- [x] test-writing-guidelines に `test('TC-xxxx:` 宣言行の要件表と GOOD/BAD 例を追記
- [x] ADOPT_QUALITY_SETUP テンプレートがルールと `--tc` 確認を参照
- [x] `npm --prefix src run lint` が成功する

### Changes

**Summary 1 — テスト記載ルールの機械連携セクション**

フォーマットAを `test('TC-xxxx: ...')` に修正し、`--tc` 単体実行・test-results.json 結合・UI コマンド表示が依存する宣言行契約を表形式で明文化した。

**Summary 2 — adopt 品質キット手順の参照**

`quality-kit.ts` の ADOPT_QUALITY_SETUP にルール参照と `npm --prefix src test -- --tc` 確認ステップを追加した。

### Outcome

adopt 先や新規テスト作者が、人間可読な命名と機械可読な TC 宣言を同じルールで学べる。`--tc` が効かない原因を「宣言行不足」と切り分けられる。
