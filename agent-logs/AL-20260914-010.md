## Content

### Objective

**課題:** `traceweave serve` は古い `src/dist` を読み込むため、ソースに FR/NFR 集計が追加されても API が `undefined` を返し、ダッシュボードで 0 件表示になっていた。手動の `build:cli` / `build:web` が必要だった。

**対応:** `serve` 起動時に CLI コンパイルと Web フルビルドを自動実行するフローへ変更し、1 コマンドで最新のレポートが配信されるようにする。

### Completion Criteria

- [x] `traceweave serve` 起動前に CLI が再コンパイルされる
- [x] `serve` 起動時に Vite バンドルと `data.json` が毎回再生成される
- [x] `/api/data` が FR/NFR 件数を正しく返す
- [x] `npm --prefix src run lint` が成功する
- [x] `npm --prefix src test` が成功する

### Changes

#### serve 用のフル Web ビルド

`prepareServeDashboard` を追加し、`serve` コマンドから `skipViteIfPresent: true` の部分ビルドをやめた。起動のたびに Vite バンドルと `data.json` を再生成し、静的フォールバックも API レスポンスと揃える。

#### bin ラッパーでの CLI 事前コンパイル

`bin/traceweave`（bash / cmd / ps1）で `serve` 実行時に `build:cli` を Node 起動前に走らせる。プロセス内に読み込まれる `build-report` が常に最新の dist になるよう、古いコンパイル済みコードによる FR/NFR 欠落を防ぐ。

### Outcome

`traceweave serve` だけでダッシュボード用の CLI・Web・データが再ビルドされ、FR/NFR などの集計が手動ビルドなしで正しく表示される。
