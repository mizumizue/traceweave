## Content

### Objective

**課題:** lint/test は通過している一方で、コンパイル済み CLI のパス解決、`serve` のパストラバーサル、`check` とスキーマ検証の乖離、UI 偽装フォールバック、DocParser の無言失敗、MCP 未テスト、adopt-project モノリスなど、実運用で効く問題が残っていた。

**対応:** 機械検証とコード探索で P0〜P3 を優先度順に洗い出し、ルート解決の共通化・境界ガード・検証統合・テスト追加・モジュール分割まで一連で修正する。

### Completion Criteria

- [x] `resolveRepoRoot` により source/dist 両経路で docs・reports を正しく参照する
- [x] `serve` 静的配信が dist 外パスを 403 で拒否する
- [x] `checkDocs` が `validateDocs` スキーマ検証を含む（REQ-0005）
- [x] InteractiveTestRunner のクライアント側偽装フォールバックを削除する
- [x] DocParser パース失敗を `check` 警告として表面化する
- [x] MCP ツール契約のテスト（TC-0042）を追加する
- [x] `deepEquality` 共有化、adopt-project 分割、`report --format html`、テスト高速化を実施する
- [x] superseded 要件を未テストギャップから除外し `traceweave check` 警告ゼロにする
- [x] `npm --prefix src run lint` および `npm --prefix src test` が成功する

### Changes

**P0 正確性・セキュリティ.** 深さ推測の `projectRoot` を `resolveRepoRoot` に置き換え、コンパイル CLI でも `docs/` と `reports/` を安定参照できるようにした。`serve` は `isPathInsideRoot` でパストラバーサルを 403 拒否。`validateDocs` を `src/infrastructure/governance/` に移し `checkDocs` から呼ぶことで REQ-0005 のスキーマ検証ギャップを解消。InteractiveTestRunner のブラウザ内スコア計算フォールバックを削除し、API 不可時はエラー表示のみとした。

**P1 信頼性・保守性.** DocParser は `getLastWarnings()` で frontmatter 欠落・パース例外・不正 parameter JSON を記録し、`check` の `[parse]` 警告へ連携。MCP は `tool-handlers.ts` にロジックを抽出し TC-0042 で 4 ツール契約を検証。`deepEquality.ts` へ深い等価比較を集約し TestRunnerRegistry から委譲。

**P2〜P3 構造・カバレッジ.** adopt-project を 7 モジュールに分割。`npm test` は dist 未生成時のみ web ビルド（`test:ci` で常時ビルド）。superseded/deprecated 要件をギャップ集計から除外。`HtmlReporter` と `report --format html` で SPEC-0010 の CLI SVG フォールバックを充足。関連テストを追加・強化。

### Outcome

利用者は `traceweave check` でスキーマとトレーサビリティを一括確認でき、警告は有効要件のみに絞られる。`serve` 経由の UI テスト実行はサーバー API 正本のみ。`report --format html` でゲージ付き HTML を得られる。開発者は dist 済み環境で `npm test` の待ち時間を短縮できる。
